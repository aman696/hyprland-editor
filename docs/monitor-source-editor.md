# Captured monitor source editing

In the captured-source inspector, select a **Monitor declaration**, then **Compare a Source Change**. Choose a field or output selector. Existing fields offer **Set value** and, except for required `output`, **Remove field**. Absent fields offer **Add field**. Set a proposed value, then compare before keeping it. Value changes can target the selected expression or a traceable original literal. Existing monitor builders provide resolution/modeline, arrangement, scale, transform, color, mirroring, reserved-space and profile controls. Output names and profile paths remain ordinary data inputs. Keeping the comparison creates a private source revision; it does not modify the captured original or apply a desktop change.

The restricted worker freshly rebuilds each comparison from immutable, hashed source bytes. An expression in another captured file can be selected through recorded value provenance. The expected argument change is compared with the new argument observations, loader requests, executed decisions, return values and logged errors. If a shared literal changes other declarations, the review lists those changes. Incomplete analysis remains incomplete. Keeping a private revision uses the existing source fingerprint, draft generation, task epoch, closed-window and single-flight checks; input changes invalidate pending results. Private pieces use the existing bounded undo and `.hye` representation.

## Field presence and source preservation

An addition can target the selected constructor, a traceable original constructor in another captured file, or the recorded last write. If the last write explicitly cleared the slot with `nil`, the GUI selects that write. A new explicit string key is inserted directly after the opening brace, preserving implicit array indices and avoiding existing line comments. A recorded `nil` constructor placeholder is reused rather than creating duplicate keys. An insertion at an earlier constructor can still be masked by a later write; the comparison reports that it did not establish the requested observation.

Removal follows the selected raw key's recorded latest write and table identity. Constructor fields and their adjacent separators are removed with small source patches; genuine comments and whitespace remain. Assignment/rawset writes keep their other targets and receive an explicit `nil` at the recorded value expression. This removes the slot at that write without resurrecting a prior initializer. Native defaults and inherited rules are not computed. Required exact `output` cannot be removed, but unknown string fields and conflicting NUL/alias spellings can be removed individually. Duplicate constructor storage order still stops the evaluator; this is not a repair engine for arbitrary unresolved Lua.

Computed keys are matched through fresh storage evidence, not guessed from their text. Cross-file/shared tables can affect other declarations; these effects remain visible. Small patches preserve unrelated module requests. Partially changed surviving loader requests require renewed resolution input. A wholly removed request loses its captured resolution in the materialized revision; inserted code never inherits that resolution. Multi-patch review validates every patch's document/hash/range, shows before/after excerpts, and bounds the visible report. Full-expression replacement still replaces the selected expression; the layout-preserving choices below retain supported table internals.

## Reserved-area table layout

For an existing `reserved` or `reserved_area` gap table, **Preserve table layout and comments** changes the owned sides while retaining genuine comments, separators, line endings and unrelated fields. It is selected initially for a directly observed table constructor. **Original table layout, if traceable** follows recorded value history to a reached constructor, including another captured file. Signed sides remain allowed. Unchanged components retain their original spelling when the primary codec proves the same parsed value, including accepted numeric strings.

Missing sides are inserted using explicit keys; existing nil placeholders are reused. This operation refuses computed keys, unsupported constructor shapes, external fields and untraceable original tables instead of falling back to whole-expression replacement. Native primary equality is checked again after retained fields are combined with the proposal. The ordinary source comparison still reports shared uses, masked later writes and effects removed from changed component expressions. Layout preservation does not establish exclusive ownership or effective monitor state. Other monitor fields use their existing typed value controls; full-expression replacement remains an explicit choice.

## Whole declarations

In the inspector's **Files** pane, select a captured file and choose **Add / Remove Monitor Declaration**. This works even when the file has no observed declarations. Add an empty rule or copy a selected typed monitor draft, choose its output match, and select a statement boundary. Beginning/end positions are available; end placement precedes a final return. Keep the comparison before using the source field controls to extend the new declaration. Copying a draft does not establish ongoing synchronization with it.

Removal lists statically spelled `hl.monitor` calls, including unobserved nested sites, and modeled calls through aliases. Observation counts and source output hints describe captured analysis only. Removing a site removes all its modeled invocations. Standalone calls are erased while retaining genuine comments and whitespace. Embedded calls become a zero-result inert expression so Lua return-list/vararg arity is retained. Changes to callee/argument effects remain separate review findings. Unknown aliases and unresolved source remain incomplete.

The worker rebuilds each operation from the captured program and exact syntax coordinates. Explicit insertion/removal intentions are compared with the complete remaining API/loader order, arguments, path decisions, returns and logged errors. An insertion on an unreached path is not reported as an observed match. Alignment refuses more than 4,000,000 sequence cells (about 8 MiB for its length matrix); it never clips a comparison into success. Inventories refuse more than 100,000 syntax nodes or 4096 combined statement/declaration sites. Inventory collection is lazy for one selected file, without hardware polling.

When removal makes captured dependencies unreachable, their original documents and resolution evidence remain in the saved base graph. Only the materialized revision drops their unused bindings; reopening first validates the complete original graph. Removing original request bytes does not grant new filesystem access. These private revisions use the same compare/keep, input invalidation, stale-result guards, bounded undo and save/reopen path as field edits.

## Explicit draft reconciliation

Choose **Review Monitor Drafts** in the captured-source inspector. The initial choice is **Keep separate**. Select a reached source declaration and a draft rule explicitly; repeated output names are not identities. The review can copy one source observation into a selected draft rule, append it, replace the entire draft sequence with reached observations, write a selected draft into an existing declaration, or insert it into a selected captured file. The insertion review offers beginning/end placement; the separate declaration editor offers exact statement boundaries.

Copying requested values does not copy conditional code or derive effective monitor state. A partial analysis can supply a visible individually selected observation, with a prominent incomplete/provisional caption; replacing the whole sequence requires completed analysis and every reached declaration to be representable. Unknown/rejected fields, NUL keys and conflicting aliases remain visible as reasons to review source first. Existing draft identities/order are retained when replacing one rule. Whole-sequence replacement uses the observed source order, including repeated output selectors, and validates the 64-rule limit and existing mirror constraints.

Writing rebuilds the selected declaration field by field: remove explicitly omitted known fields, update requested values, then add absent fields through recorded nil writes or an original constructor. Every step requires its full modeled comparison to match. Shared-table changes, removed argument/callee effects, masked writes, partial analysis and multiple reached invocations of one syntax site require separate source review. Known invalid values and missing output selectors can be repaired, but unknown or ignored source fields are not erased by reconciliation. After all steps, field presence and every primary parsed value are checked again. Unchanged equivalent inputs retain their original spelling; directly selected reserved-area tables use the layout-preserving edit.

Compare shows the proposed monitor draft and bounded before/after source excerpts. Input changes invalidate pending comparisons, and changed source/draft generations or closed views discard results. Keeping independently rebuilds the private pieces and checks the reviewed resulting program identity before changing the source graph and monitor draft together. Both changes share one bounded undo entry; history-budget refusal happens before mutation. Save/reopen uses the existing schema-pinned monitor and graph representations without opening original paths. This is an explicit one-operation reconciliation, not persistent synchronization or a proof of complete language/native helper/effective behavior.

## Evidence and model boundaries

`scripts/monitor_source_probe.py --check` temporarily downloads the two hash-pinned `LuaBindingsConfigRules.cpp` sources, extracts their original `hlMonitor` function, and runs 43 reviewed cases per version with inert field-parser/application/manager/refresh adapters. It verifies all 22 descriptor names and factory declarations. Original downloads and builds are removed on exit. This certifies routing/output coercion/continuation observations only. Adapter success is not evidence for a real value parser, monitor helper, rule replacement or hardware result.

The Rust inspector combines that routing model with the existing independently checked Bool/Int/Float/String/CssGap primary codecs and source-declared bounds. It preserves original key bytes, requires the exact `output` field, applies the handler's C-string dispatch truncation separately, ignores non-string keys, and identifies both reserved-area aliases and embedded-NUL key collisions. It never selects a winning alias using its own table order. It models submission/refresh requests even when other fields are rejected. These flags describe handler control flow; they cannot authorize execution.

The original handler can inherit an existing rule for the same output, and exact output lookup can invoke `__index`. The evaluator refuses unmodeled metatable operations and unknown table contents before observing calls; it must not replace those with raw-table guesses. The inspection API consumes modeled table observations, not arbitrary real Lua tables. Effective values, inherited rule contents, native helper application, ICC file contents, integer narrowing and physical output matching remain unverified. Factory constructor text is retained as declaration metadata, never an effective/default value.

The source model accepts numeric output coercion for inspection. A proposed output is explicit text matching the editor's selector constraints. Proposed field values must pass both editor input validation and the primary codec. Conflicting aliases cannot be edited as though one had exclusive ownership. Rejected/unrepresentable inputs use a labeled proposed starting value; that value is not presented as the current state or an effective default. A missing or invalid output selector can be repaired graphically. Source numeric controls retain exact integer values and use exact numeric entries when a monitor draft control would clamp or round the input. Conflicting aliases offer removal without pretending that one spelling exclusively owns the property.

Each inspection is limited to 256 ordered monitor observations, 4096 root rows per table, bounded event/batch envelopes and 2 MiB retained output. The coordinator additionally verifies version, schema, linked compiler profile, numeric locale, event order and absent runtime claims before retaining results. Existing parser process restrictions and time/memory limits remain in force. There is no polling loop for monitor hardware.

## Remaining work

This supports values, field presence and whole-declaration changes within the captured model. It does not implement general recovery of unresolved source operations, general trivia-preserving recovery of unsupported expressions, reconciliation against changed original graphs, persistent monitor/source synchronization and general unresolved-declaration reconciliation, legacy monitor import, native helper/manager semantics, live hardware discovery, apply/recovery or rendered preview. These remain part of the full audit and must not be counted as complete from this milestone.
