# Captured monitor source editing

In the captured-source inspector, select a **Monitor declaration**, then **Compare a Source Change**. Choose a field or output selector. Existing fields offer **Set value** and, except for required `output`, **Remove field**. Absent fields offer **Add field**. Set a proposed value, then compare before keeping it. Value changes can target the selected expression or a traceable original literal. Existing monitor builders provide resolution/modeline, arrangement, scale, transform, color, mirroring, reserved-space and profile controls. Output names and profile paths remain ordinary data inputs. Keeping the comparison creates a private source revision; it does not modify the captured original or apply a desktop change.

The restricted worker freshly rebuilds each comparison from immutable, hashed source bytes. An expression in another captured file can be selected through recorded value provenance. The expected argument change is compared with the new argument observations, loader requests, executed decisions, return values and logged errors. If a shared literal changes other declarations, the review lists those changes. Incomplete analysis remains incomplete. Keeping a private revision uses the existing source fingerprint, draft generation, task epoch, closed-window and single-flight checks; input changes invalidate pending results. Private pieces use the existing bounded undo and `.hye` representation.

## Field presence and source preservation

An addition can target the selected constructor, a traceable original constructor in another captured file, or the recorded last write. If the last write explicitly cleared the slot with `nil`, the GUI selects that write. A new explicit string key is inserted directly after the opening brace, preserving implicit array indices and avoiding existing line comments. A recorded `nil` constructor placeholder is reused rather than creating duplicate keys. An insertion at an earlier constructor can still be masked by a later write; the comparison reports that it did not establish the requested observation.

Removal follows the selected raw key's recorded latest write and table identity. Constructor fields and their adjacent separators are removed with small source patches; genuine comments and whitespace remain. Assignment/rawset writes keep their other targets and receive an explicit `nil` at the recorded value expression. This removes the slot at that write without resurrecting a prior initializer. Native defaults and inherited rules are not computed. Required exact `output` cannot be removed, but unknown string fields and conflicting NUL/alias spellings can be removed individually. Duplicate constructor storage order still stops the evaluator; this is not a repair engine for arbitrary unresolved Lua.

Computed keys are matched through fresh storage evidence, not guessed from their text. Cross-file/shared tables can affect other declarations; these effects remain visible. Small patches preserve unrelated module requests. The normal source planner refuses patches that destroy a loader request or observation boundary; it does not silently invent resolutions. Multi-patch review validates every patch's document/hash/range, shows before/after excerpts, and bounds the visible report. Compound value replacement still replaces the selected expression; only the separate scalar layout operations preserve compound internals.

## Evidence and model boundaries

`scripts/monitor_source_probe.py --check` temporarily downloads the two hash-pinned `LuaBindingsConfigRules.cpp` sources, extracts their original `hlMonitor` function, and runs 43 reviewed cases per version with inert field-parser/application/manager/refresh adapters. It verifies all 22 descriptor names and factory declarations. Original downloads and builds are removed on exit. This certifies routing/output coercion/continuation observations only. Adapter success is not evidence for a real value parser, monitor helper, rule replacement or hardware result.

The Rust inspector combines that routing model with the existing independently checked Bool/Int/Float/String/CssGap primary codecs and source-declared bounds. It preserves original key bytes, requires the exact `output` field, applies the handler's C-string dispatch truncation separately, ignores non-string keys, and identifies both reserved-area aliases and embedded-NUL key collisions. It never selects a winning alias using its own table order. It models submission/refresh requests even when other fields are rejected. These flags describe handler control flow; they cannot authorize execution.

The original handler can inherit an existing rule for the same output, and exact output lookup can invoke `__index`. The evaluator refuses unmodeled metatable operations and unknown table contents before observing calls; it must not replace those with raw-table guesses. The inspection API consumes modeled table observations, not arbitrary real Lua tables. Effective values, inherited rule contents, native helper application, ICC file contents, integer narrowing and physical output matching remain unverified. Factory constructor text is retained as declaration metadata, never an effective/default value.

The source model accepts numeric output coercion for inspection. A proposed output is explicit text matching the editor's selector constraints. Proposed field values must pass both editor input validation and the primary codec. Conflicting aliases cannot be edited as though one had exclusive ownership. Rejected/unrepresentable inputs use a labeled proposed starting value; that value is not presented as the current state or an effective default. A missing or invalid output selector can be repaired graphically. Source numeric controls retain exact integer values and use exact numeric entries when a monitor draft control would clamp or round the input. Conflicting aliases offer removal without pretending that one spelling exclusively owns the property.

Each inspection is limited to 256 ordered monitor observations, 4096 root rows per table, bounded event/batch envelopes and 2 MiB retained output. The coordinator additionally verifies version, schema, linked compiler profile, numeric locale, event order and absent runtime claims before retaining results. Existing parser process restrictions and time/memory limits remain in force. There is no polling loop for monitor hardware.

## Remaining work

This supports values and field presence for modeled captured declarations. It does not implement whole monitor declaration insertion/removal, general recovery of unresolved source operations, source trivia preservation inside replaced compound value expressions, reconciliation against changed original graphs, monitor-draft/source reconciliation, legacy monitor import, native helper/manager semantics, live hardware discovery, apply/recovery or rendered preview. These remain part of the full audit and must not be counted as complete from this milestone.
