# Workspace draft editor — 0.8

Native source-model reference checks now cover 78 argument-routing cases and 42 userdata/method cases across both pinned versions, with explicitly inert dependencies. They establish reference observations for the next source-editing implementation; the ordered evaluator still stops at this API. A closed post-inspection rule/object state library is now implemented and tested, but argument inspection and the source evaluator/GUI connection remain unfinished. See the [workspace source-model plan and evidence](workspace-source-model.md).

Open **Menu → Edit Workspaces**. This editor stages ordered private workspace declarations, with all 15 audited fields, the workspace selector, optional enabled state and retained typed layout options. It never creates a workspace, runs an empty-workspace command, changes a layout or writes the original configuration.

Choose a declaration and one field at a time. Set This Field distinguishes an override from absence. Explicit false, zero, empty strings and border-size -1 remain literal values. Field and declaration switches retain valid form edits; invalid forms block switching. Add, duplicate, reorder, remove and undo work on the staged list. Save Draft records all editor families and any source snapshot in the private schema-pinned workspace. Closing an invalid form offers a discard choice; closing a valid form stages it in memory.

Workspace Selection offers numbered, named and special addresses, all-existing-workspace matching, and AND filters for number ranges, special/named status, display-name prefix/suffix, monitors, window/group counts with tiled/floating/pinned/visible flags, and fullscreen states. Filters describe existing workspaces, not instructions to create them. Action/navigation selectors such as relative/previous/empty-workspace queries have a different grammar and are not substituted into this builder. Unrecognized imported spellings stay literal and explicitly unresolved. Untouched selector spelling is retained, including whitespace and aliases.

The common filter builder uses source-defined numeric/version bounds and protects bracket-delimited values from clause injection. It does not implement a runtime matcher or certify every permissive legacy spelling. Current bare named-address forms, hexadecimal spellings and unusual boolean aliases may remain literal rather than editable clauses. Actual monitor selectors still need a full graphical shared builder; the filter's monitor argument is a literal input. Source parsing checks only the declaration structure and selected values, not the existence of a live workspace or monitor.

Known layouts have a picker, retaining imported custom names. Master orientation and scrolling direction have mapped choices; unknown/non-string imported option values are visibly retained and are not converted just by opening the form. Other custom layout options survive import/save/export unchanged. Full custom-option authoring, layout messages, visual custom layouts, animation-style builders and empty-hook command workflows remain outstanding. Generic gap bounds are editor policy, not complete upstream parser conformance.

Check Declaration Order explains identical-selector merging. The actual upstream `replaceOrAdd` finds the first enabled declaration with the same literal selector and calls `mergeLeft`; that merge does not copy enabled state. Therefore a later disabled declaration can change fields in an earlier enabled rule without disabling it. Nonempty monitor strings replace prior monitor values; empty monitor strings do not. False/zero/empty optional values remain real overrides, and layout-option keys merge. Default workspace selection uses the first enabled default whose monitor matches. Literal consolidation and findings are distinct from runtime rule matching.

An optional `python3 scripts/workspace_source_probe.py` check fetches the exact source files recorded in `data/workspace-semantics.json`, verifies SHA-256 and compiles the reviewed merge/default-order functions against inert C++ fixture data. Temporary files are removed. It starts no compositor or Lua interpreter and runs no configured command. This narrow source comparison does not certify monitor matching, selector evaluation, Lua argument conversion, graphics, persistent workspace creation or hardware behavior. Layout-option numbers are preserved as original typed literals; upstream string conversion is not simulated.

Static `hl.workspace_rule` tables and restricted pure locals import without Lua execution. Unknown expressions invalidate later load-time API trust. Existing private workspaces default to no workspace declarations; nonempty new snapshots require the workspace schema pin. Declaration policy limits are 1,024 rules, 128 options per rule and 1 MiB serialized data; the filter builder has 32 clauses. These limits do not establish a memory ceiling or support arbitrary configuration size.

Workspace source spans, insertion/deletion, changed-source reconciliation and legacy workspace-rule import are not implemented. Scalar source-copy review is blocked when it would omit workspace changes. Scalar comparison retains structured drafts. Runtime discovery, default/persistent creation semantics, complete selectors/layout/workflow codecs, real parser interoperability, isolated preview and guarded apply/recovery remain required. None of the full WORKSPACE contracts is release-certified by this milestone.
