# Editing shortcuts that use local variables

Import a `.conf` and open **Edit Bindings**. Preceding source definitions such as `$mainMod` and `$terminal` can now populate the ordinary shortcut controls. Known aliases and reassignments are processed in source order. The editor uses only captured file text; it does not read the live shell's environment, evaluate includes or execute a command. These are source-derived values, not observations of the running compositor.

Changing one field preserves references in the others. For example, changing a key leaves an unchanged `$mainMod` modifier and `$terminal` command reference in the source copy. Changing the command replaces that field with the explicit value you chose. Definitions and other uses remain unchanged. **Review Binding Config** remains an explicit literal fragment; the main **Review Source Copy** preserves source references and comments.

Each source-backed row retains its original declaration link in the private project. Duplicate and reorder carry these links, including when two rows currently have identical values but refer to different variables. If moving a reference across a later reassignment would change its value, source export refuses the ambiguous copy. Open **Add, reorder or remove entries → Use Literal Values for This Entry** to explicitly detach the selected row before exporting. This freezes its current field values; undo restores the source links. No other row or variable definition changes.

![Variable-derived shortcut controls](screenshots/legacy-bindings.png)

Projects written by the earlier literal-only codec keep their previous view, edits and deliberate empty targets. They do not automatically acquire or remove variable-based declarations. **Review Variable-Based Shortcuts…** prepares a proposal from the captured source with your literal edits already applied. Inspect the proposed entries, then choose **Use Variable-Aware View** or **Keep Literal-Only View**. Acceptance changes the private draft and can be undone. Save a new project to retain that choice; the older file and original configuration are not overwritten. Reopening needs neither original file nor folder access.

Only complete identifier references with known preceding local values are resolved. Names may contain letters, digits and underscores. Unknown or forward/ambient values, expressions, braced references, unsupported name patterns and partial-prefix substitutions remain unresolved. A variable cannot inject additional prefix argument columns; ordinary final command arguments may contain commas. Literal source and unresolved declarations remain retained.

Unknown includes and unresolved dynamic directive names invalidate earlier local knowledge. A literal submap reset restores known binding scope but does not restore unknown variable values. A new explicit definition can make that name known again. Conditional, continued and nested declarations retain the existing conservative handling. Quotes, hash escapes and backslash/brace escapes follow the pinned lexer rather than shell syntax.

The reader retains at most 1,024 active names and 256 KiB of known values, with a 64 KiB bound on an individual expansion. Input and binding projection remain bounded to 1 MiB; expansion growth is checked while collecting rows. The source links add bounded history accounting. Parsing and upgrade preparation use the existing restricted worker on demand, with no polling or global input hook.

This increment resolves variables only for supported legacy bind/submap/unbind declarations. Graphical editing of definitions or reference expressions themselves, general expressions/prefix macros, includes, ambient inputs, variable use in other families, complete action argument builders and verified effective behavior remain required. Actual isolated preview, guarded live apply/recovery and full resource/security/release acceptance remain unfinished. Ordinary preview preparation continues to omit native binding operations without command, description, device or submap payloads.

The native variable definition/substitution behavior is pinned to [hyprlang's parser](https://github.com/hyprwm/hyprlang/blob/090117506ddc3d7f26e650ff344d378c2ec329cc/src/config.cpp) in the current binding profile. The exact earlier profile is frozen at `data/legacy-bindings-v1.json`. The [reviewed source-model transition](graph-model-migration.md) retains captured inputs and existing compiler observations. A source link is provenance inside captured text; it grants no filesystem authority. No downloaded source repository is retained.
