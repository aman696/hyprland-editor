# Explicit private import resolution

When a composed configuration reaches a new or changed import, **Resolve Imports…** opens a separate proposal. Each choice supplies exactly the first observed request, including its loader, source bytes, call range, package path and working-folder context. Original captures are independently rebuilt and replayed before inspecting the private program. The client and restricted worker must agree on the complete materialized program fingerprint. The pending proposal is not a saved, accepted graph.

Three explicit input modes are available:

- **Capture from allowed folders:** allow a folder for this review, then capture the requested file. Folder descriptors are new temporary capabilities; no saved path restores access. The existing loader-specific search order, before/after metadata observations, held-folder containment and source identity checks apply. Inspect the captured snapshot before choosing **Use This Input**. Forgetting a folder drops its live grant; already captured bytes remain immutable data and never become permission to read again. A failed or exhausted search does not silently supply a missing-module result.
- **Use a preserved view:** inspect an original, private or archived source, including its private edits, then select it for this exact request. Selection alone does not activate archived data. Its historical path and current existence remain unverified. Fresh capture never substitutes an edited or byte-equal inserted view for the newly captured bytes.
- **Assume this import is missing:** a separate acknowledgement supplies an explicit missing-input assumption to the model. This is not a filesystem absence observation or a claim about native/custom searchers. The resulting analysis can remain partial.

After each accepted input, fresh replay discovers the next request. **Undo Last Input** restores the immediately previous proposal; this review retains one previous step. Source inspection is read-only and uses UTF-8-safe 16 KiB pages. **Verify Inputs and Return** performs normal saved-graph reconstruction and reached-input checks, then returns the proposal to the final merge review. It does not change the application draft. Only the parent's existing **Keep Merge in Draft** action commits root/origin/graph together with one inverse; the separate private save and reopen workflow still applies.

For a materializable unresolved proposal, **Review Unresolved Draft** provides the existing explicitly acknowledged partial-result path. A changed inherited import may still require exact resolution inputs before normal reconstruction can retain it. This action does not invent a missing assumption or add an empty input layer to bypass that requirement. An analysis that stops before reaching a changed request cannot manufacture an exact input for it.

The resolver binds the parent's version, draft generation, retained graph, root hash, review epoch and pending-program fingerprint. Changed choices, draft changes, closure or destruction invalidate it. Returning data cannot change original captures or the reviewed source pieces. Closing the resolver cancels its operation and releases its proposal, one-step history, preview and temporary grants; in-flight helpers retain their own handles only until their bounded operation finishes. Results from stale operations cannot update the review.

Parser cancellation now checks before serialization/executable selection/spawn, during 10 ms child polling and after completion. An owned child is killed and reaped before pipe threads are joined on cancellation or timeout; unwinding also drops the child through this cleanup. The existing 3-second parser wall limit, 4 MiB envelope, syscall restrictions and child resource limits remain. Folder observation/capture helpers and pure client work retain their existing bounds; this is not a guarantee of immediate interruption of every operation or a production sandbox certificate.

Each resolver allows at most eight live folders, 128 explicit private bindings and the existing 32-document total, including archives. Capture/replay retain their existing byte, observation and time limits. These operation bounds do not certify representative process-tree memory, latency or maximum-size workflow support. Wildcard directory loading remains unresolved until ordered directory-snapshot semantics exist; it cannot be represented by guessing one file.

Verification covers both pinned Hyprland snapshots and all four loader forms, actual restricted replay and fresh folder capture, grant release before retention, deletion/replacement of captured files, refusal without grants, explicit archived private-piece activation, missing acknowledgement, foreign requests, cancellation and document-limit refusal. Private-display workflows exercise sequential inputs, one-step undo, parent return before draft mutation, save/reopen/undo, draft/choice/close/destroy invalidation and narrow-window layout. Deterministic owned-child tests separately verify cancellation, timeout and unwind reaping. The session checkpoint records executed results; test references alone are not certification.

Complete language/native semantics, effect and ownership review, general source insertion/deletion/export, persistent history, broader resource/platform/accessibility behavior, real compositor preview, guarded apply/recovery and every original audit/security/release gate remain required.
