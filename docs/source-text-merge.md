# External-source merge foundations

The core now compares an original captured document, its private edited bytes and an incoming captured revision. This is the text and view-correspondence backend for graph-wide reconciliation. The graphical external-graph acceptance path remains unfinished and continues to refuse single-file replacement of a retained graph. Explicit text decisions can now produce a private piece layer on the incoming captures, and the application has a combined root/origin/graph inverse transaction for the eventual acceptance path.

## Exact text choices

The line-level shortest edit script is refined by Unicode scalar positions inside changed regions. A bidirectional middle partition uses linear frontier space. Separate edits can merge within the same line; conflicting replacements require a choice. Insertions at a replacement boundary retain their relative position, and different insertions at one boundary offer explicit private-first/incoming-first ordering. Identical observed changes are retained once. No whitespace, newline, Unicode normalization, comment or string-literal cleanup runs, and no conflict markers are inserted into source.

Repeated text can make an unchanged anchor optional. Before accepting apparently separate changes, a second shortest-path search forbids the relevant exact equality edge. If an equally short alignment still exists, the affected edits enter an ambiguous-alignment conflict. The engine does not infer which repeated line the author intended. Related regions can be enlarged conservatively rather than guessing a source identity.

Each review binds the three complete input hashes/lengths and current model identity. It accounts for every original byte and independently reconstructs every private/incoming byte, in order, from input-labelled ranges. Resolution requires every conflict choice, refuses foreign/automatic-region choices and independently checks the selected ranges, final bytes and hashes. Results always report syntax, ownership and runtime verification as false. Imported strings remain data; this layer does not parse or execute Lua.

The two restricted-worker operations are `ReviewSourceMerge` and `ResolveSourceMerge`. The existing envelope, child memory/CPU/wall-clock, descriptor and syscall restrictions remain in force. Inputs are at most 1 MiB each and reject NUL bytes. Default limits additionally bound abstract work to 32 million units, anchor proofs to 8192, frontier cells to 4,194,312, regions to 4096 and selected fragments to 8192. UTF-8 boundaries and the existing 1 MiB result limit are checked. Budget exhaustion returns an error with no merge output; it never becomes a coarse overwrite or a successful truncated result. These are mechanism bounds, not a whole-process memory or latency certificate.

The shortest-path background is the Myers middle-snake algorithm. Google's archived [primary diff-match-patch implementation](https://github.com/google/diff-match-patch/blob/master/python3/diff_match_patch.py) was inspected as an implementation reference. This project's Rust tokenization, bounded scripts, mandatory-anchor checks, region/provenance model and tests are original code. No upstream source download or dependency is retained by this implementation.

## Graph correspondence

`workspace_graph::merge` binds both full captured graph identities, their pinned compiler/version assumptions, path context and private piece revisions. Module IDs are sequential capture labels and can change when dependency order changes. Suggestions therefore compare exact selected-path bytes plus load names; they preserve hardlink/load-name distinctions, with no inode-based or content-equality relocation guess. Roots remain the explicitly selected root pair. Ambiguous matches and relocations require explicit correspondence choices, and a new view cannot be assigned to two old views.

Every old view needs a counterpart or removal choice. Removing a privately changed view requires its exact explicit discard acknowledgement. Root/home/inherited search-path/working-folder context changes require review. Added incoming views remain part of the incoming graph; recommendations do not discard them. A lazy file-input operation binds one mapped document's original/private/incoming bytes to the whole correspondence and both graph fingerprints. It never opens the recorded paths and never restores filesystem grants. Correspondence reports do not claim syntax, dependency replay or ownership verification.

## Private composition and atomic state transition

`workspace_graph::merge::compose` freshly rebuilds the graph correspondence and every mapped file's exact text review/choices. Missing, extra, stale and forged decisions are refused. Incoming sources and historical bindings remain immutable. Incoming-labelled fragments become monotone original ranges; selected private/base fragments become interned inserted buffers. Equal bytes alone never turn inserted text into captured provenance. Unmapped new incoming views stay in the new baseline, while removed private changes still need their exact discard acknowledgement. Aggregate inserted-byte/piece limits and the streamed 8 MiB decision/bundle envelope bound retained output and hashing allocations.

Composition returns a candidate with syntax, dependency replay and ownership verification false. Changing a surviving captured loader span reports dependency renewal; the old input is not copied to the changed request. The separate [private input layer](private-dependency-inputs.md) now stores and reconstructs explicitly supplied private documents/bindings, with independent replay and archival checks. Fresh-folder resolution choices and the graphical composition/acceptance flow still need integration; later external reconciliation currently refuses a nonempty private layer instead of dropping it.

The application transaction checks the reviewed generation, version, parsed root hash, captured identity and graph root before recording any mutation. Root document, origin, graph and explicitly removed scalar overrides share one bounded inverse; separate typed families remain unchanged. Identical refreshes create no history entry. A stale/mismatched/oversized operation leaves state and existing history intact. Shared root allocations are counted once across source-only and combined inverse entries, separately from graph snapshot allocations. This transaction is an internal acceptance primitive; it does not make an unreviewed merge acceptable or enable the blocked single-root comparison UI.

## Evidence and remaining work

The core suite checks shortest edit costs and mandatory equality edges against an independent dynamic-programming oracle for 3,969 short sequence pairs and 500 deterministic multi-symbol cases, plus 3,375 small three-way combinations for full branch coverage, selected output and UTF-8/provenance checks. Additional cases cover CRLF/final newline, normalization distinctions, comments, same-line edits, conflicting values/insertions, repeated-line ambiguity, stale/forged input and explicit budget failures. A 4,000-block sparse-change case exercises the linear-frontier path. Composition fixtures exercise both snapshots, immutable incoming bytes, private root/module changes, explicit dependency renewal and refused decisions. An actual application subprocess reopens the composed private graph after both original capture trees are removed. Application transaction fixtures check combined root/identity/graph/override undo, separate typed data, private serialization, stale/mismatched inputs, graph absence and inverse-budget failure. Graph correspondence fixtures cover both pinned snapshots, module renumbering, logical load views, removed private changes, ambiguous/relocated counterparts, context changes, root preservation and stale correspondence. Actual worker requests check resolution, false execution claims and forged-review refusal. These tests establish their stated scopes only.

Still required for the external multi-file workflow: fresh incoming graph capture under current explicit grants; graphical file/correspondence/conflict choices; preservation or explicitly reviewed disposal of removed/private source data; graphical integration of the provenance-aware composition and atomic state transaction; graphical fresh-folder resolution and private-view correspondence/preservation for new/changed loaders without borrowing textual resolution rights; independent syntax/dependency replay of the complete merged graph; whole-workflow root-document/origin/graph/history acceptance and persistence; race/failure/resource/accessibility checks. A text merge or path match cannot substitute for any of these stages, E03/E05, full ownership or the original release/security gates.
