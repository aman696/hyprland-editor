# External-source merge foundations

The core now compares an original captured document, its private edited bytes and an incoming captured revision. This is the text and view-correspondence backend for graph-wide reconciliation. A graphical path now captures a fresh incoming graph, reviews file/context and text choices, independently rebuilds the inputs and keeps a materializable result under one root/origin/graph inverse. Single-file replacement of a retained graph remains refused. Complete changed-import resolution, archive activation and general source ownership remain unfinished.

## Graphical review

With a retained source graph, open the source dependency view and choose **Merge Incoming Configuration…**. Allow a folder, capture the incoming main file and analyze its dependencies under those temporary handles. **Review Merge…** opens a separate immutable proposal; it does not replace the current root. Incoming analysis and the result inspector hide edit actions so an inspection cannot modify the draft underneath the proposal. Reopening review from the same capture window focuses its existing merge window. Closing the capture window releases its folder handles; an already opened merge window retains only captured data.

The review has three focused pages:

1. **Files**: pair every saved original/private/archived view with a fresh incoming view, keep it as an inactive archive, or explicitly discard it from this draft. Roots stay paired. A disclosure shows capture identity and hashes; a separate disclosure shows both main-file/home/working-folder/inherited/initial-search contexts, including unknown versus known-empty assumptions. Changed context requires acknowledgement. A destination cannot be reused by two files.
2. **Text**: compare each mapped file's original, private and incoming bytes. Select a conflict region and its result, including explicit insertion ordering where accepted by the core. Confirm each file's choices before rebuilding. The viewer uses UTF-8-safe 16 KiB pages so every byte remains reachable without loading a whole large document into the text widget. Only one file's full input strings are retained by the viewer; confirmed decisions contain hashes/ranges/choices. Reflecting an unchanged selector does not discard those decisions.
3. **Result**: fresh restricted-worker reconstruction checks the old graph, incoming graph and composed result. The inspector exposes active files and modeled call order. Keep Merge in Draft commits the captured root, identity and merged graph with one undo, preserving separate typed drafts and overrides. Save Draft writes a new private workspace. Original paths are not reopened by reconstruction and no live configuration is written.

A changed surviving loader range still requires renewed resolution inputs before composition can be retained. That resolution UI remains unfinished. A materializable result whose analysis stops elsewhere stays explicitly partial; keeping such a private draft requires a separate acknowledgement and grants no runtime/preview/apply certificate. New imports are not automatically satisfied from archived or equal-looking old data.

Every operation binds the current version, generation, original root hash and retained graph fingerprint. Changed choices invalidate the candidate. A single source-operation lease bounds concurrent work. Closing a window or changing the draft invalidates pending results and sets cancellation; workers and pure merge operations finish within their existing bounds before the lease is released. This is cooperative cancellation between bounded calls, not a proof of immediate interruption or a production process/resource certificate. The existing 4 MiB worker envelope can refuse otherwise structurally valid large graphs; general maximum-size workflow support remains required.

The compact native step switcher, wrapped acknowledgements and disclosures preserve the existing system theme. Both-version private-display cases capture under an approved folder, close its access, remove source files, choose a real module conflict and preserve an invalid-Lua archive, rebuild/keep, save/reopen and undo the graph/root change while retaining a separate scalar override and monitor draft. Held work is rejected after a generation change or closure. The content-width check requires a minimum of at most 350 px and an actual 350–360 px allocation in the private X11 fixture. These cases establish their stated scope only; broader accessibility, platform, performance and arbitrary-language behavior remain unverified.

## Exact text choices

The line-level shortest edit script is refined by Unicode scalar positions inside changed regions. A bidirectional middle partition uses linear frontier space. Separate edits can merge within the same line; conflicting replacements require a choice. Insertions at a replacement boundary retain their relative position, and different insertions at one boundary offer explicit private-first/incoming-first ordering. Identical observed changes are retained once. No whitespace, newline, Unicode normalization, comment or string-literal cleanup runs, and no conflict markers are inserted into source.

Repeated text can make an unchanged anchor optional. Before accepting apparently separate changes, a second shortest-path search forbids the relevant exact equality edge. If an equally short alignment still exists, the affected edits enter an ambiguous-alignment conflict. The engine does not infer which repeated line the author intended. Related regions can be enlarged conservatively rather than guessing a source identity.

Each review binds the three complete input hashes/lengths and current model identity. It accounts for every original byte and independently reconstructs every private/incoming byte, in order, from input-labelled ranges. Resolution requires every conflict choice, refuses foreign/automatic-region choices and independently checks the selected ranges, final bytes and hashes. Results always report syntax, ownership and runtime verification as false. Imported strings remain data; this layer does not parse or execute Lua.

The two restricted-worker operations are `ReviewSourceMerge` and `ResolveSourceMerge`. The existing envelope, child memory/CPU/wall-clock, descriptor and syscall restrictions remain in force. Inputs are at most 1 MiB each and reject NUL bytes. Default limits additionally bound abstract work to 32 million units, anchor proofs to 8192, frontier cells to 4,194,312, regions to 4096 and selected fragments to 8192. UTF-8 boundaries and the existing 1 MiB result limit are checked. Budget exhaustion returns an error with no merge output; it never becomes a coarse overwrite or a successful truncated result. These are mechanism bounds, not a whole-process memory or latency certificate.

The shortest-path background is the Myers middle-snake algorithm. Google's archived [primary diff-match-patch implementation](https://github.com/google/diff-match-patch/blob/master/python3/diff_match_patch.py) was inspected as an implementation reference. This project's Rust tokenization, bounded scripts, mandatory-anchor checks, region/provenance model and tests are original code. No upstream source download or dependency is retained by this implementation.

## Graph correspondence

`workspace_graph::merge` binds both full captured graph identities, their pinned compiler/version assumptions, path context, private piece revisions, private captures and archives. Module IDs are sequential capture labels and can change when dependency order changes. Suggestions therefore compare exact selected-path bytes plus load names; they preserve hardlink/load-name distinctions, with no inode-based or content-equality relocation guess. Roots remain the explicitly selected root pair. Ambiguous matches and relocations require explicit correspondence choices, and a new view cannot be assigned to two old views.

Every original, private and archived view needs a counterpart or removal choice. Removing private data requires an exact, separate archive or discard choice. This includes unchanged private captures, existing archives and byte-equal inserted-piece revisions; equality does not erase their provenance. Unchanged original views may also be archived explicitly. Mapped views cannot also be archived or discarded. Root/home/inherited search-path/working-folder context changes require review. Added incoming views remain part of the incoming graph; recommendations do not discard them. A lazy file-input operation binds one mapped document's original/private/incoming bytes to the whole correspondence and both graph fingerprints. It never opens the recorded paths and never restores filesystem grants. Correspondence reports do not claim syntax, dependency replay or ownership verification.

## Private composition and atomic state transition

`workspace_graph::merge::compose` freshly rebuilds the graph correspondence and every mapped file's exact text review/choices. Missing, extra, stale and forged decisions are refused. Incoming sources and historical bindings remain immutable. Incoming-labelled fragments become monotone original ranges; selected private/base fragments become interned inserted buffers. Equal bytes alone never turn inserted text into captured provenance. Unmapped new incoming views stay in the new baseline, while removed private data still needs its exact archive or discard choice. Aggregate inserted-byte/piece limits and the streamed 8 MiB decision/bundle envelope bound retained output and hashing allocations.

Composition returns a candidate with syntax, dependency replay and ownership verification false. Changing a surviving captured loader span reports dependency renewal; the old input is not copied to the changed request. The separate [private input layer](private-dependency-inputs.md) now stores and reconstructs explicitly supplied private documents/bindings, with independent replay and archival checks. The correspondence/composition backend now includes active private inputs and archives in later external reconciliation. Mapped private modules merge their original/private bytes onto the selected fresh incoming capture. Removed views can retain their immutable source identity, load name and exact piece revision as inactive private archives. Local ID collisions receive explicit old-to-new labels; source paths and capture metadata are not rewritten. No original or private resolution binding is copied from the old graph. Fresh incoming bindings can survive only under the existing incoming-range provenance rules. A preserved import therefore still needs fresh resolution if its chosen text no longer has an incoming binding. Archives do not activate themselves to satisfy it. Total document/source/piece/buffer/envelope limits include the preserved data, and exhaustion refuses the candidate without dropping requested archives. Fresh-folder resolution choices for changed private requests and archive reuse/activation still need integration.

The application transaction checks the reviewed generation, version, parsed root hash, captured identity and graph root before recording any mutation. Root document, origin, graph and explicitly removed scalar overrides share one bounded inverse; separate typed families remain unchanged. Identical refreshes create no history entry. A stale/mismatched/oversized operation leaves state and existing history intact. Shared root allocations are counted once across source-only and combined inverse entries, separately from graph snapshot allocations. This transaction is an internal acceptance primitive; it does not make an unreviewed merge acceptable or enable the blocked single-root comparison UI.

## Evidence and remaining work

The core suite checks shortest edit costs and mandatory equality edges against an independent dynamic-programming oracle for 3,969 short sequence pairs and 500 deterministic multi-symbol cases, plus 3,375 small three-way combinations for full branch coverage, selected output and UTF-8/provenance checks. Additional cases cover CRLF/final newline, normalization distinctions, comments, same-line edits, conflicting values/insertions, repeated-line ambiguity, stale/forged input and explicit budget failures. A 4,000-block sparse-change case exercises the linear-frontier path. Composition fixtures exercise both snapshots, immutable incoming bytes, private root/module changes, explicit dependency renewal and refused decisions. An actual application subprocess reopens the composed private graph after both original capture trees are removed. Application transaction fixtures check combined root/identity/graph/override undo, separate typed data, private serialization, stale/mismatched inputs, graph absence and inverse-budget failure. Graph correspondence fixtures cover both pinned snapshots, module renumbering, logical load views, removed private changes, ambiguous/relocated counterparts, context changes, root preservation and stale correspondence. Actual worker requests check resolution, false execution claims and forged-review refusal. Additional both-version fixtures cover private-to-fresh capture mapping, edited original/private archival, unchanged and invalid-Lua archives, byte-equal inserted provenance, collision-safe labels, exact preservation/discard choices, stale archive reviews and aggregate document-limit refusal. An actual application subprocess and the separate scalar staging worker reopen an external merge with edited and invalid-Lua archives after all source files are removed; a subsequent review still requires explicit archive choices. These tests establish their stated scopes only.

Still required for the complete external multi-file workflow: graphical fresh-folder resolution/reuse for changed or new private requests; explicit archive reactivation and complete source disposition/effect review; whole-workflow failure/race/resource/accessibility coverage; general unresolved-language/ownership handling, full source export and persistent history. Current private draft acceptance is not a text/source ownership, E03/E05, runtime or original release/security certificate.
