# Edit captured declarations graphically

Open a retained project's **Ordered Calls**, select a device, binding/submap, workspace rule, window/layer rule, curve, animation or gesture declaration, then choose **Edit / Compare This Declaration**. Open **Edit declaration fields…**, change the existing graphical controls, close that editor, and choose **Compare**. Review the proposed source patch and any additional findings before **Keep in Draft**. **Save Draft / Save Project As…** retains the source revision; the Files view can review/export the complete materialized file. Undo restores the previous project source.

Use the family form's **Add**, **Duplicate**, ordering and **Remove** controls to replace the selected declaration with several declarations or remove it. Static submaps containing representable bindings can be renamed, have their reset/contents changed, or be removed as a group.

In **Files**, **Add a Declaration…** starts with an explicit feature prompt. Choose a device, binding, submap, workspace/window/layer rule, curve, animation or gesture template, edit its controls, then Compare and Keep. The insertion goes at the selected file's end before its final module return. Monitor insertion/removal retains its existing separate action. Switching templates discards stale loads, with at most one template request in flight.

The family form has an isolated temporary draft. Updating its fields does not change the project until Keep. It also does not change the separate whole-family drafts or the running desktop. Scalar and monitor declarations continue using their existing source editors.

Fields can come from a static declaration or captured modeled values, including module returns, local variables and computed expressions. A whole-declaration edit rebuilds arguments from that captured snapshot: computed links become explicit values. Shared variables and other source statements remain unchanged. Original comments within the replaced arguments are retained inside the new argument list; their exact spacing/placement is not preserved. The source review displays the replacement.

The restricted worker reconstructs source selection and arguments independently, validates the typed draft, serializes it with the existing family codec, reparses that output, and compares the complete captured graph. Callee spelling and surrounding source are preserved. Captured loader positions/hashes are rebased; other calls, loader inputs and enclosing submap contexts are compared. Input actions and imported Lua bytecode are never invoked. Parsed arguments do not prove native acceptance, hardware behavior or effective runtime state.

The editor selects one reached standalone declaration or one file insertion point. A rebuild can contain multiple declarations from the selected feature family; window/layer rules share a form, as do animation/curve and binding/submap declarations. Source replacements explicitly pair the old declaration sites with the new calls; an insertion into replaced text cannot bypass its removal intention. Comments from removed/rebuilt calls are retained, while other source statements keep their bytes.

Submaps that load modules, contain unrelated feature families or use unsupported callbacks still require individual child edits; their contents are not silently discarded. Sites reached repeatedly, consumed native objects, cycles and unrepresentable callbacks remain explicitly refused. Broader dynamic/shared ownership, all-family draft reconciliation and complete configuration relocation remain unfinished.

Current evidence includes both audited snapshots and edits, insertions, duplications and removals for devices, bindings, workspace/window/layer rules, curves, animations and gestures in captured modules. Additional cases cover computed values/shared variables, unchanged comments and surrounding source, nested submaps, later captured loaders, unchanged/type/count refusal and repeated/consumed source sites. The private graphical fixture uses the actual Files Add action and device/submap forms, rapid template switching, duplication/removal, comparison, Keep, undo and complete project persistence after original deletion. The existing full graphical fixture separately exercises every family editor.

The reconstruction model has 89 inputs and 23 exact reviewed predecessors. The current increment adds structural family editing and paired replacement intentions to the existing declaration editor and worker routing. Saved input formats/compiler profiles remain unchanged; all six preceding numeric-aware writers retain existing compiler observations. Migration reconstructs from retained bytes and restores no folder access.

Complete multi-file draft reconciliation and combined export/relocation, unrestricted dynamic source editing, full legacy structured editing, isolated compositor preview, live apply/recovery and all original release obligations remain required. This feature makes selected captured declarations editable with the existing graphical forms.
