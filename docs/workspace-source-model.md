# Workspace source-model implementation

Workspace drafts already have graphical forms and static projection. Connecting them to arbitrary captured source additionally requires ordered rule identity, returned userdata and method effects. The current ordered evaluator still stops at `hl.workspace_rule`; the reference checks below do not change that behavior or enable source editing.

## Executed native reference scope

`scripts/workspace_argument_probe.py --check` verifies 78 cases across the two pinned snapshots. It fetches the exact audited handler files, checks their SHA-256 identities and API registration, extracts all fifteen factory descriptors, compares their keys/types with the draft catalogue and compiles the original callback. Field parsers/apply functions, workspace selector, manager, refresher and returned-object push are explicit inert adapters. Their actual behavior is not certified. Temporary source/build files are removed on success or failure; no repository checkout is retained.

The cases cover required table/selector checks, numeric selector coercion, exact boolean enabled handling, unknown/nonstring/NUL keys, layout-option coercion and invalid entries, metatable lookups, ignored pairs overrides, extra arguments, per-field delegation and continuation after a controlled parser refusal. Successful routing requests one object result; missing/invalid required arguments return no results. Factory arguments remain declared metadata, not effective defaults or proof of accepted field combinations.

`scripts/workspace_object_probe.py --check` verifies 42 additional cases using the original userdata allocation, member lookup, equality, getter, setter and string-formatting bodies. Weak references are real C++ weak pointers and userdata is allocated by the original push function. Rule state, refresh and metatable registration are explicit adapters. Trusted ref/drop fixture functions expose live/shared/expired situations without a compositor. This does not certify actual manager/reload lifetime, generic metatable protection or native state effects.

The object cases distinguish wrapper identity from referenced rule identity, validate unbound method receivers, check exact setter boolean requirements, expired getter/setter behavior and equality of expired references, exercise NUL method aliases and extra arguments, and verify pointer-free live/expired string-format outcomes. Literal consolidation/default-order checks remain separately covered by `scripts/workspace_source_probe.py`; these evidence scopes are not interchangeable.

Immutable observations and factory metadata are in `data/workspace-argument-fixtures.json`, `data/workspace-object-fixtures.json` and `data/workspace-argument-semantics.json`. CI independently regenerates and compares both new fixture sets. These are 120 reference observations, separate from ordinary Rust case counts and full audit acceptance.

## Implemented closed-state stage

`workspace_rule::source_state` now models literal selector consolidation, separately allocated userdata wrappers, enabled-state methods and ordered field/option retention. A matching enabled record retains its enabled flag when a later declaration merges into it. Method mutations can change which earlier record is the first enabled match. Empty monitor values do not replace an earlier monitor; optional false/zero/empty values and unknown field/option findings retain their distinctions. Byte selectors/options are preserved without UTF-8 conversion or numeric/name normalization.

References belong to one in-memory model realm. Their fields are private and they have no serialization/deserialization implementation or constructor from saved IDs. Foreign references are refused. Methods are unbound and validate the explicit receiver and required boolean before checking target lifetime. Equality distinguishes wrapper identity from referenced-rule identity. Expired states are exercised through a trusted test fixture; there is no production observer claiming knowledge of actual manager/reload lifetime. Live string formatting exposes only its known prefix and an address-dependent marker, never an invented pointer string.

This is a post-inspection state library: known field values must already have passed independent primary parsing and option strings must already have undergone native conversion. Type/shape checks here do not establish those source preconditions, source ownership, native selector resolution, effective compositor values or native application. Unresolved fields/options carry explicit cause IDs. The ordered Lua evaluator remains stopped at this API until argument/result modeling and cross-family effect handling are connected. A regression verifies that linking the state library does not silently enable the call or continue past it.

Nine ordinary tests cover the state/method model, all fifteen post-parse field storage shapes, literal/byte identity, uncertainty, foreign references, budget refusal and the unchanged Lua barrier. A driver correlates state operations with all 42 native object scenarios, including return outcomes, modeled refresh counts and final enabled records. Member-number conversion and exact Lua error diagnostics remain responsibilities of the argument/evaluator layers; typed model rejections are not native error strings. Existing source-extracted manager checks remain separate evidence for literal consolidation.

The default hard limits are 1,024 rule slots, 4,096 wrappers, 8,192 attempted mutation steps and 4 MiB of encoded records plus a fixed wrapper metadata charge. Inputs are streamed through a 1 MiB encoding limit; fields, options and strings have explicit shape/size bounds. Byte-key option maps encode as ordered key/value pairs. Refusals preserve existing rule data and retained-byte accounting; attempted work can still consume its step budget. Toggling enabled state accounts for the changed boolean without copying retained strings/options. These are modeled bounds, not allocator or whole-process memory/latency certification. Primary parsing, full Lua provenance, cross-analysis correspondence, GUI, persistence/editing and every later acceptance stage below remain required.

The object probe additionally emits `data/workspace-object-semantics.json`, containing exact metatable/member routing and source identities. Saved reconstruction pins both workspace metadata files and the state implementation. Its reviewed compatibility transition adds the dormant library and metadata without changing Lua routing or the saved representation; unknown payloads remain refused.

## Required implementation sequence

1. **Ordered state and identities.** Represent rule records and userdata wrappers separately with bounded indices. Model literal selector consolidation, enabled filtering, per-field presence and retained layout options using the reviewed manager behavior. Multiple wrappers can refer to one rule. Method values are unbound functions and validate the explicit receiver. An uncertain external lifetime stays unknown; it cannot become a guessed live handle or a dispatch to the real session.
2. **Argument and result model.** Reconstruct required/optional lookups and distinguish raw keys from consumed C-string names. Use the existing source-pinned primitive codecs for field parsing, with exact integer/float representations and unresolved conversions retained. Preserve absent/false/zero/empty values. Layout-option number/string conversion, native errors and parser continuation need their own exact findings. Model callback arity and returned-object truth/type/identity without substituting a zero-result observer. Unsupported metatables, selectors, values or effects retain explicit barriers.
3. **Cross-family observations.** Add ordered workspace and method mutations to the event/value provenance model and restricted worker protocol. Audit scalar and monitor comparisons, source/override reconciliation, path/load/return comparisons and projection for the new event/result shapes. Existing logic explicitly admits only settings/monitor routing; adding a recognized call must not hide additional shared-value or rule-state effects.
4. **Source editing.** Rebuild field/declaration coordinates independently. Support selected expressions, traceable original literals, table-preserving insertion/removal and ordered declaration changes. Preserve opaque source, comments, number/string spelling and load provenance. Compare intended values plus unaffected calls, loader/path behavior, returns and object state. Empty-workspace hooks remain data and require effect classification; no imported hook executes during analysis.
5. **Graphical integration and persistence.** Present source declarations and method/lifetime findings, typed comparisons, shared-use consequences and explicit reconciliation with separate workspace drafts. Keep/save/reopen/undo must preserve original captures and private pieces after source deletion. Version/generation/model/root/graph/epoch guards and owned cancellation apply to every new operation. New replay/model inputs require a fresh reviewed saved-model transition; current pins cannot be silently rewritten.
6. **Acceptance.** Compare the model with all reference cases, extend to supported Lua profiles and actual primary field parsing, test positive and refused edits through restricted workers and the private-display UI, then cover selector/manager/object interactions and representative resource bounds. Native rule matching, live discovery, actual rendering, hardware, guarded apply/recovery and the original security/release contracts remain distinct mandatory gates.

The next implementation must preserve this complete sequence. Argument observations alone do not establish a complete workspace editor, native manager certificate or any full WORKSPACE contract.
