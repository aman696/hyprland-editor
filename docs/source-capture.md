# Selected-file capture boundary

Explicit Lua/legacy import, Verify Source File and Compare Changed Source now use a short-lived capture process. A picker/CLI selection authorizes one file; source expressions, parser suggestions and saved origin paths never call this reader automatically. This is groundwork for E03/E05, not an authorized multi-file graph or a completed security gate.

## Authority and phases

1. Launch the held application executable with a fixed capture switch, empty environment and private pipes. The helper closes inherited descriptors, sets no-new-privileges, resource limits and parent-death SIGKILL, and checks the expected parent PID. It accepts a typed request with a byte-safe absolute path, not commands or code.
2. Trusted Rust resolves path components using O_PATH/no-follow descriptors. This phase can inspect filesystem metadata and symlink contents but reads no configuration file bytes. It retains the regular leaf and up to 32 symlinks; procfs magic links, nonregular leaves, oversized files, cycles and invalid paths fail explicitly. This resolution is not confined to an approved directory: it is for the explicitly selected file only.
3. Require Landlock ABI >= 3, handle every filesystem right through that ABI, and allow only READ_FILE on the held leaf. Reopening `/proc/self/fd/N` obtains bytes from that inode, rather than resolving the selected filename a second time. This is inode authority: another hard link to the same inode is also readable. Landlock does not conceal metadata. Its policy is enforced before reading configuration content; no imported Lua or parser executes in this process. The [kernel documentation](https://docs.kernel.org/userspace-api/landlock.html) describes descriptor-based rules, handled rights, and thread-local enforcement. This helper is single-threaded.
4. A separate seccomp allowlist permits only the capture's bounded reads, metadata, memory, pipe and exit operations. Network/process creation, exec, signals, dedicated mutation syscalls and ioctl are denied. Landlock denies writable/creating/truncating opens and unrelated file-content reads. Unsupported setup returns an error without falling back to an unrestricted reader. Parser workers retain their original, stricter policy with no filesystem opens.
5. Capture checks regular-file identity across reopen and size/mtime/ctime/link consistency across reading, retains selected/resolved path and symlink evidence, and hashes UTF-8 content. The parent validates the returned identity/hash and exact selected path before import or comparison. This is an immutable revision observation; later file changes remain possible and do not grant write authority.

## Budgets and cleanup

Requests are at most 32 KiB with paths at most 4,096 bytes. Replies are at most 8 MiB, allowing worst-case JSON escaping of a 1 MiB source plus evidence. The child has a 512 MiB address-space limit, 8 MiB stack, two seconds of CPU, 64 descriptors, no core dumps and a zero regular-file output-size limit. Existing descriptor/type/link and source-byte limits still apply.

The parent gives the process three seconds after spawning to exit and return pipe results. Timeout requests SIGKILL and transfers ownership of the child, pipe threads and single-flight lease to an asynchronous reaper. The GUI does not join an unfinished I/O thread or wait for child termination. The lease remains occupied until reaping and pipe cleanup actually finish, so repeated selections cannot accumulate capture children. Ordinary completion leaves no resident helper. A blocked kernel operation can outlive SIGKILL; a single quarantined child/reaper may therefore remain, and capture stays unavailable until cleanup completes. The parent-death signal is best effort under the same kernel limitation. Process creation itself and other reader roles are outside this response deadline.

Private stopped-child testing proves prompt timeout return and eventual reaping for that case. It does not certify uninterruptible FUSE/NFS teardown, every kernel/filesystem, whole-app cancellation, parent-death races, inaccessible executable startup, or large/long-running workload memory targets. These remain explicit acceptance work. Workspace/value-draft and installed keyboard metadata reads retain their existing bounded regular-file reader; they do not yet use this capture role.

## Verification and next work

Actual-executable integration fixtures read only private synthetic files. They check successful selected-inode reads, EACCES for a sibling read and selected writable open, EPERM for socket/process creation, non-UTF-8 filenames, symlink evidence, inert command text, FIFO/directory/magic-link/invalid-path/oversize/invalid-UTF-8 refusal, worst-case source escaping and wrong parent identity. A child-only inherited seccomp fixture returns ENOSYS for the Landlock API and verifies that capture fails without a fallback. The writable-open probe uses neither O_TRUNC nor a write operation. Probe/stop request variants exist only in debug builds, with no GUI routing.

Core tests additionally hold a leaf across filename replacement to prove it cannot be redirected, reject an unlinked leaf, and reject a symlink replaced between metadata resolution and capture. Existing parser fixtures recheck no file/network access and inert Lua after sharing the policy-construction utility. Existing workspace/comparison and native workflows exercise the new production routing.

Local Linux x86-64 validation passed 177 ordinary tests plus the private-display native workflow (178 total), formatting, strict Clippy, release build and catalogue/action/register consistency. The local kernel reports Landlock ABI 10. This evidence does not establish ABI 3-kernel or aarch64 runtime compatibility, remote-filesystem teardown or an independently audited sandbox.

This selected-file role does not enumerate or authorize dependency candidates. A separate [approved-folder capture role and temporary GUI review](dependency-capture.md) now supply live directory grants and contained explicit file reads. Complete external target/ownership review, graph identities, bounded wildcard/cycle/miss evidence, ordered static replay, module returns/cache identities, graph persistence/reopen/history and multi-file source codecs remain required. The full 1,453-contract audit and preview/recovery/resource/release obligations remain unchanged.
