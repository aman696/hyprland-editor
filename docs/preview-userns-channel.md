# User-namespace channel experiment

The ordinary editor still has no rendered preview. The next ignored CI fixture tests the existing pidfs channel with both a private PID namespace and UID/GID translation. It does not install a privileged production helper or change the rootless Bubblewrap refusal observed on Ubuntu 24.04.

The GUI role remains in the provider's user/PID namespaces. The broker role must be PID1/parent0 with inside UID/GID1000 mapped only to the non-root fixture user's outside UID/GID. It verifies exact single-entry maps, a different user-namespace identity, private proc containing only its own process, empty supplementary groups/capabilities and no-new-privileges. The actual existing endpoint/peer implementation must accept a sealed synthetic frame and the reverse receipt across these translated credentials. No numeric-PID fallback is allowed.

This is explicitly a privileged ephemeral CI setup experiment. Root creates the same bounded private cgroup and future-child PID namespace as before. Only fixed system setup executables receive setup privilege. A fixed outer setpriv changes to the non-root fixture user and retains only SYS_ADMIN for the private mount/proc constructor. It makes mount propagation private before mounting proc inside the already-private PID namespace. A second unshare creates self-only user/group mappings, then an inner setpriv removes every capability, bounding/ambient/inheritable bit and retains the already empty supplementary-group list before any repository role executes. The kernel's denied-setgroups state after the group mapping is respected. No subordinate-ID database or host security policy is edited.

Mounting the private proc first matters: mapping tools and role checks must never interpret namespace PID1 as the host's init through an inherited host proc mount. The parent provider's current user/mount/PID namespace identities must remain unchanged. Its whole private hierarchy is killed and removed after success or failure. Setup/system binaries are trusted; only explicit frame/channel/process-anchor FDs cross into the broker. Host-directory and cgroup-control FDs do not.

Two independent kernel jobs for `57958e2802de38c189006ab6b6aee58d494858a2` now passed the exact mapped exchange. Both recorded UID/GID maps `1000 1001 1`, sealed pixels, the reverse receipt, unchanged provider namespaces and private hierarchy removal. [Source/tool/log identities and observations](../data/preview-ci-userns-observation.json) retain the scope. The complete enclosing workflows are tracked separately. This verifies translated credentials for these trusted roles on the recorded kernel, not executable/projection attestation, a closed runtime filesystem, syscall/network/device isolation, a malicious broker, real compositor capture/input, production launch or crash supervision. The rootless runtime-image and pidfs observations used different kernels and are still not a combined production profile. Full E09 and all original audit/release/security gates remain required.
