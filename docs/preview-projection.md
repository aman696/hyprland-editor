# Fresh typed-draft preview projection

`hyprland-editor-projection` builds new Lua and a review report from a validated private workspace and an explicit synthetic scenario. It has no filesystem, IPC, process or compositor API. The application now provides [restricted staging and a graphical preparation review](preview-preparation.md). It starts no compositor; a projection's content identity is never execution authority. The complete source-layer compiler, reviewed asset bundle and actual compositor integration remain required.

## Inputs and emitted declarations

The builder validates the exact workspace/schema and typed declarations before generating anything. It reuses the existing versioned exporters for both pinned snapshots and covers scalar values, monitors, devices, workspaces, window/layer rules, curves/animation nodes, bindings/submaps and gestures. Declaration order is retained. The generated bytes are compiled and independently reparsed with the linked Lua profile; no imported Lua is executed. This checks syntax, not native setter acceptance or renderer behavior.

Without a selection, only explicit typed draft values participate. The optional [setting-value review](preview-setting-layers.md) reconstructs captured scalar arguments and private revisions, requires explicit choices and checks native representation after emission. Original source bytes, modules, plugins and hooks are never copied into executable output. Non-scalar source behavior still receives omission/unsupported entries. This is not effective configuration reconstruction: complete structured source/override layers, defaults and native manager effects remain mandatory compiler work. The input fingerprint binds the complete validated workspace, including omitted/mocked changes, without disclosing command arguments in the report.

The report identifies each projected declaration, source omission, action mock and hardware/asset exception. Labels are SampleApproximation, MockedEffect, OmittedUntrusted, HardwareUnverified or Unsupported. No PrivateCompositorVerified label can be produced. Eleven schema identities, the emitter model identity, linked compiler profile, exact upstream commit and scenario bind the projection identity. The model identity is not a package signature or whole-runtime certificate; the future launcher still needs approved executable/library/profile identities.

## Scenario identities and resource bounds

Scenarios request one to four private `HEADLESS-` names with bounded dimensions and at most 1280×720 aggregate pixels. These are requests, not proof that a backend created those outputs. The future launcher must create and read back the exact private identities. Initial geometry is horizontal, scale 1 and 60 Hz; capture transport's separate 15 FPS bound is unchanged. Actual rendering/memory acceptance remains unmeasured.

Monitor and device draft IDs need explicit scenario mappings; unknown/stale mappings fail. Unmapped declarations are reported and omitted. Device destinations must use the synthetic `hye-lab-` namespace. There is no implicit host-name or hardware fallback. Monitor mode, topology, transform, mirror, disabling and ICC requests are omitted in favor of the bounded scenario, with hardware/fidelity entries. Remaining monitor/device fields are requests with unverified physical semantics. Device keymap paths/output references and scalar host-output references require future private asset/identity support and remain omitted.

The output is limited to 1 MiB, the report to 16,384 entries and 4 MiB, and the workspace to its existing private serialization bounds. An overflow fails the entire projection; it does not return truncated code or silently remove later declarations. Application staging now runs in a [supervised bounded worker](preview-preparation.md). The library itself supplies no cancellation, CPU/I/O deadlines or cgroup placement. A family exporter may allocate its already-bounded intermediate text before the aggregate output check. Representative peak/idle memory measurements remain required.

## Effects and assets

All binding and gesture action constructors become pinned inert `no_op` actions, preserving deferred/at-load shape and callback phase order. Built-in gestures other than `unset` become an inert finish workflow. Reports retain constructor/builtin labels and IDs, not original command arguments. These are placeholders without mock telemetry or simulated layout/process/session effects. They must not be presented as verified action behavior.

Workspace empty-command hooks are omitted. Opaque screen shaders, external keymap paths and ICC files are not read, copied or referenced in generated code. Complete reviewed font/keymap/ICC/image assets and generated shader templates remain required; arbitrary source paths never gain read authority from this report. Rule/workspace host-monitor assignments are omitted until their scenario mapping is implemented. Rich selectors can still fail to match the synthetic scenario; the report does not certify selector/effect fidelity. Scenario/client construction and complete accepted-domain behavior remain open.

## Verification and compatibility

Six checks cover both snapshots, all nine scalar families and every structured declaration family, ordered curve/node emission, every audited action constructor's inert replacement, original source/commands/asset payload exclusion, explicit hardware mappings and refusal, stale pins, geometry limits, deterministic identities, changed omitted-input fingerprints and an oversized valid action draft's refusal. Fresh generated Lua passes the linked compiler and independent syntax tree. Five additional library tests and one real-worker integration test cover explicit scalar selections, stale/partial/rejected values, all nine native families/sign bits, original-byte preservation and module private-piece reconstruction after deleting originals. The extended native workflow exercises selection and partial acknowledgement. No test starts Hyprland, executes imported code, reads an imported path or changes a desktop.

The new workspace member updates Cargo dependency fingerprints in the existing conservative saved-graph model pin. Three exact previous graph models now have an [explicit reviewed migration](graph-model-migration.md), rebuilt through current restricted workers and saved only as a new private copy. Other incompatible models remain refused; general model/schema conversion is unfinished. The application links the internal library but runs compilation only in the short-lived staging child; whole-product resource and migration acceptance remain open.

All source editing/history/export, effective discovery, independent recovery/live apply, hardware, accessibility/localization, packaging and the full original release/security gates remain mandatory.
