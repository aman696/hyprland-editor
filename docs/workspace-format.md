# Private source-backed workspace format

Experimental format: `hyprland-editor-workspace-1`, file extension `.hye`. This is an editor-owned draft artifact, not an active Hyprland config, parser cache or publication plan. Storage uses the existing private 0700 app directory, 0600 immutable files and descriptor-relative atomic no-overwrite publication. The data, temporary-name removal and app directory are synced; first creation also syncs the app directory entry in its parent.

The JSON contains the draft, a schema pin (exact upstream commit and SHA-256 of bundled scalar metadata), an optional root document ID and source records. Each record contains a bounded stable document ID, source language, exact UTF-8/NUL-free bytes and origin evidence: selected and resolved path bytes, recorded symlink targets/identities, SHA-256, descriptor device/inode, owner/mode, byte size and modification/change timestamps. Paths are byte arrays to preserve non-UTF-8 filenames. They are display/provenance data; decoding a workspace never opens them and cannot authorize a writer.

Structured monitor/device/binding/workspace/rule/animation/gesture drafts are separate from the source projection. Each nonempty structured model pins its schema. Gesture callbacks retain static action blocks and optional unused parameter names; schema or model-shape tampering is refused. Reopening preserves edited drafts while reparsing the original saved source bytes.

Explicit Lua/legacy source selection resolves relative, absolute and directory symlinks through held descriptors and records the chain (at most 32 links). Procfs links, broken links, cycles, non-regular targets and oversized files are rejected. The reader opens only the held regular leaf for I/O, checks byte/metadata consistency and rechecks held link identities after capture. It records the kernel-resolved leaf path and classifies store paths, symlink-managed sources, other-owner, read-only or user-owned sources. These classifications are provenance, not write capabilities or full generated-file ownership analysis. Private workspace/value-draft reads retain their no-follow final-component policy. Recorded path display escapes control/bidi characters and invalid UTF-8 bytes. Old identities without optional resolved-path/link fields remain readable. This is not an include/dependency graph or a filesystem sandbox; explicitly selected regular files can still be on remote/FUSE filesystems without a hard I/O deadline.

Limits are 8 MiB serialized, 4 MiB cumulative source content, 32 documents, 1 MiB per source and 64 ASCII ID characters. IDs must be unique, roots must exist, and source size/hash must match the stored bytes. Unknown fields, duplicate draft setting IDs and foreign schema pins are errors. GUI/CLI restoration supports one Lua root or an explicitly retained frozen Lua graph with schema-pinned load views and resolution inputs. Multi-file snapshots without that graph metadata, and legacy snapshots, are refused. Graph source editing remains unfinished. Value-only workspaces are supported. Older `.json` value drafts remain importable.

Parser spans/reports are not serialized. Reopening reparses the stored root in the restricted worker and reconstructs retained graphs from their source bytes and saved inputs in that worker using the workspace's exact snapshot; opaque behavior remains diagnosed, and edited values remain distinct from the imported declaration projection. Reopening does not rewrite the workspace, original files or live settings. Catalogue mismatches require a future explicit migration, with the old artifact preserved.

**Verify Source File** opens only the file explicitly selected in the file chooser. Bytes must match the recorded revision. Exact metadata/path identity verifies the revision; a path, link-chain, inode, permission or timestamp difference is an identical relocation that needs a concrete identity review. Changed bytes cannot silently rebind a draft. The separate **Compare Changed Source** action performs reviewed single-root static declaration reconciliation. It compares the previous snapshot, draft and explicitly selected captured source. Independent changes can merge; conflicts need choices. Opaque/diagnosed projections require acknowledgement and never interpret unresolved fields as absent. Full multi-file reconciliation remains outstanding. The captured origin is replaced only after a non-stale review, and origin changes participate in unsaved guards.

Saving runs outside the GTK thread. Completion marks a draft saved only when its generation still matches the submitted revision. An older successful save remains a valid artifact but cannot clear later edits. Failed saves retain the existing model and report the error. A headless `--check-workspace` command uses the same restore/parser path and reports its static scope and unverified runtime status.

The existing save location is separate from known config targets. **It has not passed the blueprint's watched-source-graph certification**, particularly for opaque computed dependencies. No automatic checkpointing or live publication is introduced at this milestone. Complete persistence safety requires discovery of watched roots/wildcards or an independently verified persistence target; the warning in the README is not that proof. Retention quotas, checkpoint history, multi-file changed-revision merge and a recovery journal remain outstanding.

Accepted comparisons change the draft and stored root snapshot in memory, then require Save Draft to persist them. Reviews bind source/report/draft/catalogue fingerprints and a model generation; newer edits, imports or identity changes invalidate acceptance. The source snapshot and only the changed draft values have a shared inverse operation, so Undo restores both. Neither acceptance nor undo opens or writes original paths. Source text that cannot be projected is retained verbatim, with partial-state warnings. New captured bytes may already differ from the current external file; this is not a live attachment certificate.


See [retained graph inputs](source-graph-workspace.md) for the optional `source_graph` record. Its source-model and compiler pins are separate from the original scalar/schema identity. An old app rejects that unknown field instead of silently discarding it. A saved resolution describes a past supplied input; it cannot restore live metadata observations, folder grants, a current absence certificate or source-edit authority.


Private source graphs may include optional `revisions`: document/base/current hashes, shared inserted text buffers and ordered original/inserted piece ranges. Captured `sources` and their `origin` identities retain original bytes. Reopening validates these inputs and rebuilds the private draft without reopening original paths or restoring grants. See [private revision representation and limits](private-source-revisions.md). Current revision state persists; operation history across restarts does not.
