# Private source-backed workspace format

Experimental format: `hyprland-editor-workspace-1`, file extension `.hye`. This is an editor-owned draft artifact, not an active Hyprland config, parser cache or publication plan. Storage uses the existing private 0700 app directory, 0600 immutable files and descriptor-relative atomic no-overwrite publication. The data, temporary-name removal and app directory are synced; first creation also syncs the app directory entry in its parent.

The JSON contains the draft, a schema pin (exact upstream commit and SHA-256 of bundled scalar metadata), an optional root document ID and source records. Each record contains a bounded stable document ID, source language, exact UTF-8/NUL-free bytes and origin evidence: selected path bytes, SHA-256, descriptor device/inode, owner/mode, byte size and modification/change timestamps. Paths are byte arrays to preserve non-UTF-8 filenames. They are display/provenance data; decoding a workspace never opens them and cannot authorize a writer.

Source ownership is recorded from file metadata as user-owned, read-only, other-owner or direct store path. This is not full symlink/generated ownership analysis. The reader rejects final-component symlinks and records identity from the same opened descriptor as the bytes, rejecting metadata/size changes during its bounded read. A future ownership graph must record link/target chains and separate approved capabilities before publication.

Limits are 8 MiB serialized, 4 MiB cumulative source content, 32 documents, 1 MiB per source and 64 ASCII ID characters. IDs must be unique, roots must exist, and source size/hash must match the stored bytes. Unknown fields, duplicate draft setting IDs and foreign schema pins are errors. Current GUI/CLI restoration supports one Lua root; multi-file or legacy source snapshots are explicitly refused until their lossless editors are implemented. Value-only workspaces are supported. Older `.json` value drafts remain importable.

Parser spans/reports are not serialized. Reopening reparses the stored root in the restricted worker using the workspace's exact snapshot; opaque behavior remains diagnosed, and edited values remain distinct from the imported declaration projection. Reopening does not rewrite the workspace, original files or live settings. Catalogue mismatches require a future explicit migration, with the old artifact preserved.

**Verify Source File** opens only the file explicitly selected in the file chooser. Bytes must match the recorded revision. Exact metadata/path identity verifies the revision; a path, inode, permission or timestamp difference is an identical relocation that needs a concrete identity review. Changed bytes cannot silently rebind a draft. Full three-way reconciliation is a remaining requirement. The captured origin is replaced only after a non-stale review, and origin changes participate in unsaved guards.

Saving runs outside the GTK thread. Completion marks a draft saved only when its generation still matches the submitted revision. An older successful save remains a valid artifact but cannot clear later edits. Failed saves retain the existing model and report the error. A headless `--check-workspace` command uses the same restore/parser path and reports its static scope and unverified runtime status.

The existing save location is separate from known config targets. **It has not passed the blueprint's watched-source-graph certification**, particularly for opaque computed dependencies. No automatic checkpointing or live publication is introduced at this milestone. Complete persistence safety requires discovery of watched roots/wildcards or an independently verified persistence target; the warning in the README is not that proof. Retention quotas, checkpoint history, changed-revision merge and a recovery journal remain outstanding.
