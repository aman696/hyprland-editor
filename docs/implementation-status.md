## Source persistence foundation in 0.3

Private `.hye` workspaces now retain value drafts, exact source/catalogue pins, imported Lua bytes, source hashes and descriptor-derived file metadata. Reopening uses the restricted parser again and does not access recorded original paths. Explicit file selection can verify the same revision or review an identical relocated copy; a changed revision is refused. Source identity participates in dirty-state guards. Storage is asynchronous and generation checks prevent a late save from clearing newer edits. Duplicate draft IDs are rejected, and errors are bounded before GTK display.

Core fixtures cover immutable private save/restore, deleted originals, hash tampering, unsupported schema pins, duplicate IDs/unknown fields, bounds, symlinks and byte-safe names. Real-application checks exercise restricted-worker reparse, inert opaque code and rejection of bad source/snapshots. The graphical workflow exercises source-backed saving and edits made during a save. These tests do **not** certify watched-path isolation or full E03/E05: the multi-file graph, generated ownership, full multi-file changed-revision merge, insertion/deletion and crash/recovery gates remain open.

Explicit source selection now captures symlink chains and resolved leaf identity through held descriptors. Tests cover relative/absolute/directory links, non-UTF-8 targets, cycles, broken links, linked FIFOs, procfs links, trailing-slash semantics and changed link targets with identical bytes. Saved snapshots retain link evidence without reopening recorded paths. This does not follow config includes, detect arbitrary generators or authorize a writer; remote/FUSE I/O deadlines and concurrent mutation certification remain outstanding.

## Single-root revision reconciliation in 0.4

A reviewed three-way comparison now combines clear independent declaration changes and requires choices for divergent changes, including draft/source deletion. Diagnosed or opaque source projections are conservative unresolved observations; adopting a visible syntactic literal needs a choice and acknowledgement, while unresolved absence cannot remove an override. Derived expressions in partial sources are not offered as adoptable literals. Source/report/draft/catalogue fingerprints and model generation reject stale acceptance. Both source texts are available in the focused native review; file evidence is collapsed.

Acceptance is an in-memory reducer with source-aware undo. Inverse operations retain only changed values and share immutable source snapshots. Rolling history caps at 1,000 operations or an estimated 8 MiB retained data, rejects oversized inverses before mutation, and drops oldest entries; persistent checkpoint/spill history is not implemented. Core comparison, history-budget, restricted-process comparison and narrow native workflow tests supply evidence for this single-root behavior. They do not close E03/E05 or S08 as full multi-file/live transaction contracts.
