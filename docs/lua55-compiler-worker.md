# Separate Lua 5.5 compiler worker

The `hyprland-editor-lua55` package implements a separate one-request compiler/conversion image. It has no GTK, editor-core, RE2 or Lua 5.4 dependency. Its `native55` feature is explicit; normal GUI/legacy workspace builds do not build this image or require Lua 5.5 development packages. No application code selects this image yet, and the ordered source model remains Lua 5.4.

The existing bounded C++ adapter is shared in `crates/editor-lua55/native/bridge.inc`. The legacy wrapper retains its Lua 5.4 static assertion, API symbols and two-argument constructor. The separate wrapper asserts Lua 5.5, exports different symbols and uses the three-argument constructor with a fresh private kernel-random hash seed for each state. Entropy failure is refused without a fixed fallback; bounded nonblocking retries cannot wait for entropy indefinitely. The existing four-release Lua 5.4 compiler/conversion/reference checks pass after extraction. These libraries are built into distinct executable images; Cargo feature unification does not select a different Lua in the GUI.

## Wire behavior

The exact `--compiler-worker` role requires an empty environment. After dynamic-library startup, it applies resource limits, closes inherited descriptors above stderr, makes standard pipes nonblocking, disables privilege escalation and installs the closed compiler syscall policy. This adds `ppoll` to the existing parser base for bounded waits; legacy parser and capture policies remain unchanged. Requests cannot supply a syscall list, filesystem grants, executable/library paths or an execution operation.

One JSON request contains protocol `hye-lua55-compiler-1`, a 32-byte nonce, an explicit expected Lua patch release and one operation: profile, compile, primitive conversion or the fixed denial diagnostic. Unknown fields/operations/protocols and mismatched releases are refused. Current reviewed compiler/conversion releases are 5.5.0 and 5.5.1; this does not admit either release to the ordered evaluator. Replies correlate the nonce and SHA-256 of the exact request bytes, report the actual header/runtime release/identity and observe global-declaration/identifier compilation separately. They explicitly leave complete-language and selected-compositor verification false.

Compilation accepts bounded bytes and a logical diagnostic name, uses text-only `luaL_loadbufferx`, returns exact bounded diagnostics and never invokes the chunk or opens Lua libraries. Primitive conversion accepts only nil, booleans, signed integers, binary64 bit payloads and bytes; a single private C-API state runs only the editor-owned protected conversion callback. It has no imported functions, metatables, userdata or callbacks. Number output retains bits, including negative zero and a tested NaN payload. Existing C-string truncation and integer/number/string flag distinctions remain explicit; this low-level result is not a setting parser or constraint certificate.

Limits are 4 MiB per wire direction, 1 MiB source, 4 KiB logical name/diagnostic, 256 primitive inputs, 64 KiB per primitive string and 512 KiB aggregate conversion output/accounting. Each native state has an 8 MiB allocator; the process requests 128 MiB address space, eight MiB stack, two CPU seconds, no core dumps and sixteen open-descriptor slots. Nonblocking input and output share a three-second deadline. Oversized/unfinished input or an undrained reply cannot leave this trusted implementation waiting indefinitely. A production parent must still enforce its own cancellation, deadline, output and owned kill/reap bounds, including startup and unexpected native failures. Address-space limits are not representative RSS/PSS or latency acceptance.

## Execution evidence

Ten actual process cases pass with private official Lua 5.5.0 and 5.5.1 builds. They cover compile-only language boundaries and binary rejection, inert imported effects, fixed file/network/process denial, held inherited descriptor closure, empty-environment refusal, an additional getrandom denial installed only in the owned test child to prove explicit entropy refusal, nonce/request/release correlation, unknown operations/fields, integer/float/NaN/string conversions and repeated state reset, source/name/batch/text/output refusals, actual native allocator refusal on large syntactically valid source, subsequent independent requests and unfinished-input/blocked-output deadlines. Test launchers hold the Cargo-built inode; this is an explicit test adapter, not production image authentication.

Both private builds also pass strict role lint and optimized compilation. ELF inspection requires no Lua, GTK, Adwaita or RE2 shared dependency in these private static-Lua images; actual profile replies identify the requested release. [Recorded archive/library/source/image identities and replies](../data/lua55-compiler-worker-observation.json) keep this evidence separate from the broader [source/parser reference corpus](native-runtime-compatibility.md). Temporary archives, originals, libraries and Cargo build directories are removed. The local system-linked development image was separately inspected and links only Lua 5.5 among Lua families; this does not identify the user's selected compositor.

To build explicitly on a development system with Lua 5.5 headers:

```sh
cargo build --locked -p hyprland-editor-lua55 --features native55 --release
cargo test --locked -p hyprland-editor-lua55 --features native55
```

The private release wrapper's `--worker-conformance` flag instead uses a temporary hash-pinned static Lua library and target directory. CI enables it independently for each official release alongside the source references. Hosted success must be observed for the exact published head.

## Reconstruction and next integration

The GUI still links Lua 5.4. Extraction changes the reconstruction model to 78 inputs and adds a sixteenth exact reviewed predecessor, freezing the earlier workspace-state model. Only workspace dependency metadata, the legacy wrapper/build tracking, shared adapter and unused separate-role policy addition change; Lua routing and saved representation remain unchanged. Both snapshots rebuild all sixteen exact predecessors from captured bytes. Active/archived data from all four earlier private-layer writers remain intact under fresh restricted Lua 5.4 replay. Unknown models/payloads remain refused, and migration requires review and a new private save.

Production integration must provide authenticated installed image/dependency selection and an immutable held image, bounded parent protocol validation and owned lifecycle, profile-bound source compilation/coercion/evaluation, Lua 5.5 grammar and semantics with explicit barriers, and reviewed saved-profile migration. Dynamic loading currently precedes role isolation; the worker does not certify its launcher or loader dependencies. GUI selection, stale/close/cancellation guards, complete source editing and persistence must be tested through the actual application. The original native compatibility, source-workflow, resource, preview/apply/recovery, accessibility/packaging/security and release requirements remain mandatory; this worker is one component.
