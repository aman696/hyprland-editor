# Runtime image and private boundary prototype

The editor still cannot run a compositor preview. `editor-preview::image` now stages exact reviewed runtime bytes; an explicitly ignored CI-only test composes those bytes with a private Bubblewrap root and a default-deny syscall policy for a trusted static probe. The probe is not Hyprland, a renderer, a capture broker or a production launch API. A passed probe cannot certify their different runtime requirements.

## Frozen runtime data

Manifest format 1 names an entry file and an ordered list of destination, byte length, full lowercase SHA-256 and executable bit. JSON rejects unknown/duplicate fields and is limited to 512 KiB. Validation limits 1,024 files, 64 MiB each and 256 MiB total. Paths are canonical bounded ASCII destinations under `/app`, `/usr`, `/lib`, `/lib64` or `/etc`; files cannot duplicate one another or collide with a parent directory. No symlink, mount, arbitrary mode, host source path, command argument, loader environment or readiness flag is accepted. The entry must be a nonempty executable file.

The staging caller supplies already authorized live readable regular-file descriptors in manifest order. This API opens no source pathname and does not discover/execute ELF dependencies or use `ldd`. It reads at explicit offsets into a 16 KiB buffer, hashes while copying, checks source identity/size/timestamps and EOF, and requires the expected content digest. A failed later file releases earlier copies. Source metadata checks are additional diagnostics; digest comparison binds the bytes even when metadata alone would miss a race.

Each copy is an owned memfd with permanent write/grow/shrink/seal seals. Later modification, replacement or removal of the origin cannot change captured bytes. The object retains no source FD or host directory. Its canonical order-independent identity binds entry, destinations, lengths, permissions and hashes. Serialized manifests or identities never reconstruct a live image. A matching content hash proves bytes, not provenance, approval, ABI compatibility, executable safety or permission to run them. A release still needs package/profile authenticity, exact installed executable/loader/library/asset identity and complete dependencies.

Staging belongs in a bounded supervised worker: the current capture function bounds bytes and descriptors, but does not itself provide an I/O deadline, cgroup placement, filesystem-provider isolation or cancellation. No graphical or compositor call site uses it yet. The initial staging/transfer copies and Bubblewrap's copied files must be included in peak memory measurements; the 256 MiB input bound is not a whole-lab memory claim.

## Explicit CI experiment

The existing ephemeral provider creates only a fresh bounded private cgroup and drops privilege before repository test execution. `--runtime-image-probe` requires an already compiled trusted static fixture. CI verifies the fixture has no ELF interpreter, logs its and `/usr/bin/bwrap`'s hashes/version, and invokes only the ignored exact Rust test. The developer desktop is not used for namespace setup, mounting, root operations or a compositor trial. No ancestor controller, service, AppArmor policy or global sysctl is changed.

The test snapshots the static probe and a synthetic asset, then mutates the asset origin. Its private root contains only those copies, new procfs, Bubblewrap's minimal devices, and size-bounded writable tmpfs paths. `/home`, `/run`, `/tmp` and `/state` are private; the root and runtime files are read-only. Seven fixed environment values replace the inherited environment. No host folder, host procfs, bus/display socket, input device or GPU node is bound. Image/policy descriptors are inherited only in the new child, and the probe must find no descriptor above standard I/O.

The requested boundaries are user, mount, PID, network, IPC, UTS and cgroup namespaces, fixed inside UID/GID 1000, no capabilities, no-new-privileges, a new terminal session and parent-death handling. Bubblewrap additionally disables further user namespaces within its new user-namespace hierarchy; this changes its own namespace-local limit, not a host global policy. Unsupported construction fails; there is no `*-try`, shared namespace or host-directory fallback.

The probe policy validates the native audit architecture (x86_64 or aarch64), kills mismatched architectures, and otherwise returns EPERM for unlisted calls. Its small allowlist covers static libc initialization, bounded file/proc inspection, private writes, wait/exit and AF_UNIX sockets. It necessarily allows initial `execve`; it does not distinguish a later execution. Filesystem availability constrains executables in this experiment. This is not the traced, versioned Hyprland/Mesa policy required by the blueprint. In particular, no GPU ioctl or renderer profile has been authorized.

The fixture asserts distinct namespace identities, private PID/proc visibility, recorded UID/GID maps, empty groups/capabilities, no-new-privileges/filtering, exact environment, closed descriptors, immutable runtime files, bounded writable mounts, absence of host paths/devices, and inability to connect to a real host abstract Unix listener. It also attempts forbidden network families, ptrace/process memory/pidfd authority, namespace/mount changes, io_uring, BPF, execveat and clone3. The provider kills and removes its whole hierarchy after success or failure. This is one trusted-program experiment; any result must be tied to exact source/binary/kernel/tool hashes before being reported as observed.

## Remaining execution gates

The production provider, stopped-child membership, image approval/trust chain, supported actual compositor/renderer dependencies, private user-namespace channel credential mapping, projection generation, syscall/device policy, broker protocol, real frames/input, malicious-peer flooding, GUI-loss/crash lifecycle and race-safe whole-lab teardown remain mandatory. No full E09, S11, S12, S23 or release certificate advances from this experiment alone. All original source-editing, recovery/apply, hardware, accessibility, localization and distribution requirements remain in scope.
