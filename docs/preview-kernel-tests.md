# Opt-in cgroup kernel verification

The `cgroup-kernel` CI job prepares a fresh dedicated hierarchy on an ephemeral Ubuntu runner. It exercises the actual resource-domain library without modifying the developer's desktop, selecting a desktop delegation, starting a host service or running a compositor. The corrected fixture passed both exact kernel jobs for `9dad8a55f5aa8b5a4b2198a4cf6443bcec2fcb23` on Linux `6.17.0-1022-azure`: [push job](https://github.com/aman696/hyprland-editor/actions/runs/39253034293/job/118061305442), [PR job](https://github.com/aman696/hyprland-editor/actions/runs/39253041230/job/118061329418). The [recorded observations](../data/preview-ci-resource-observation.json) retain source/log hashes, exact profiles and counters. These are kernel mechanism observations, not a certified production preview profile.

The root setup script is `scripts/cgroup_kernel_probe.py`. It refuses a non-cgroup-v2 mount, an unsuitable root or missing already-enabled CPU/memory/process controllers. It never enables an ancestor's controllers or changes ancestor limits. It creates one unpredictable private directory, limits the whole fixture to 1 GiB/256 tasks/two CPU cores, and creates a bounded driver leaf. Setup then delegates only that new private root and drops UID/GID, supplementary groups and capabilities before executing the compiled test. No root helper is installed in the application.

The Rust test is explicitly ignored in ordinary runs and requires this provider. It verifies non-root matching credentials, empty permitted/effective/bounding/ambient capabilities and no-new-privileges. Each trusted worker places itself in the intended leaf before exec, receives a live resource-directory descriptor, verifies actual limits and that it is the sole process there, and waits for the driver's membership check before starting a load. Environment text alone cannot create that descriptor. The directory token is a trusted test capability and must not be inherited by an untrusted compositor; production must close resource-control and host-directory capabilities before that execution. This is trusted fixture placement, not production stopped-child/compositor launch certification.

The default leaf profile is 512 MiB memory, no swap, group OOM handling, 64 tasks and one aggregate CPU core. Three scenarios test:

- Four runnable CPU workers with positive kernel usage and throttling counters; this fixture requires at least two available CPUs.
- Committed anonymous allocations with a kernel leaf OOM event and SIGKILL, rather than relying on a process address-space limit.
- Child creation until the task controller reports refusal, followed by whole-subtree kill with the descendants still present.

Every scenario uses the library's explicit cleanup and requires kernel absence of the removed leaf. Bounded result records report the exact counters and profile. The setup process stays outside the private hierarchy and finally kills remaining private tasks, waits for emptiness and removes only its own identified hierarchy. Failed cleanup is a failed job. Missing platform prerequisites fail explicitly, not as a passing security test.

This demonstrates only the exercised kernel mechanisms if the run passes. It does not certify hostile concurrent namespace/path substitution, production membership before untrusted execution, a verified runtime image/syscall/device policy, malicious descriptor flooding, GUI-loss/crash supervision, frame/input provenance or whole-lab release acceptance. Memory-controller accounting is distinct from GUI process-tree PSS. The [full preview scope](preview-supervision.md), [channel limits](preview-channel.md) and every original blueprint gate remain mandatory.

The first hosted attempt stopped before creating a private hierarchy because its preflight incorrectly required `cgroup.type` on the global root. The correction accepts that kernel-defined absence while requiring a normal type on the newly created private node. Four read-only metadata regressions protect this distinction and strict controller/error handling; they do not simulate cgroup filesystem authority. The kernel marks the type file [not present on the global root](https://github.com/torvalds/linux/blob/v6.12/kernel/cgroup/cgroup.c).

Both trials observed 30/31 CPU throttling events, a leaf OOM event with two reported OOM kills, and task refusal at 64 tasks / 63 processes. Every leaf and each provider hierarchy was observed empty and removed. The two full hosted workflows for that head also passed their ordinary/native/reference/lint/release checks. The developer host's delegation remains unchanged and lacks CPU; CI success grants it no execution capability.
