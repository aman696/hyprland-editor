# Private dependency input layer

A saved graph distinguishes original captures from later explicitly supplied private dependency data. `Graph.private` is omitted when empty; writers preceding the private-input model had no such field. The original graph still undergoes independent compilation/replay and exact binding/view reachability checks before any private revision is reconstructed. Historical paths and file metadata remain data, with no restored read or write permissions.

## Representation and validation

`workspace_graph::private::Inputs` contains shared immutable source snapshots, logical load views, final-private-byte resolution bindings and explicit archived source IDs. IDs must be distinct from original documents, and sources/views form a complete correspondence. Captured content must match its recorded hash and size. Private bindings carry the exact source hash/span, loader kind, module bytes, current package-path assumptions and working directory. The normal total 32-document, 4 MiB source and per-document limits include archived data; the private binding count is bounded separately at 128.

Piece revisions refer to the original bytes of both original and private captures. Only unchanged monotone original ranges retain inherited loader provenance. An explicit private layer drops inherited bindings whose loader ranges were changed; it does not reinterpret inserted equal text as an original range. Explicit bindings attach after materialization, so their hashes and ranges refer to the actual private program. Active bindings cannot refer to archived sources. An empty layer retains the existing saved-acceptance refusal for a changed surviving loader request. A separate `pending_program`/`InspectPrivateRequests` query drops changed inherited bindings before the first new input is captured, allowing fresh replay to expose the pending request. The query neither supplies a resolution nor makes a saved candidate acceptable.

A fresh restricted-worker replay must observe every private binding with its exact supplied target/loader data or explicit historical missing input, and must reach every active private document. An unused, stale, duplicate or inconsistent input is refused. Report version, language profile, compiler identity and false runtime-verification status are checked. Archived captures are excluded from evaluation and cannot resolve an import until explicitly activated and checked again. Captured syntax errors remain modeled loader observations; they are not executed or silently erased.

## Edits, persistence and presentation

Reviewed edits preserve private input data and rebase explicit binding offsets/hashes across unchanged request bytes. A changed surviving explicit request still needs renewal. Fully removing an import drops its active binding; conservatively no longer reachable private captures are retained as archives. Fresh replay still rejects bindings hidden by other control-flow changes. This is supplied-input structural reachability, not complete Lua ownership or future-effect proof.

Returning edited text to byte equality with a capture does not drop inserted-piece provenance. Only a complete original-range piece sequence permits removal of a revision. This fixes the earlier equality-based shortcut, which could have restored captured loader rights without an explicit source choice.

The application restores original inputs first, independently reconstructs the private program in its parser worker, compares the complete client/worker program identities, then replays and checks private input reachability. Frozen data survives private save/reopen without original paths. The scalar preview-layer staging worker follows the same two-stage reconstruction. Active private files appear in the existing source inspector and source comparisons. Override-only export refuses a private dependency layer. The underlying compositor preview and live apply remain unfinished.

Private source pools use shared immutable allocation across graph revisions and inverse operations. Undo counts original and private capture pools separately and counts each shared pool once. A fixture with more than 6 MiB of accounted private source data retains three graph inverses under the existing 8 MiB history budget. These are explicit mechanism/accounting checks, not a whole-process memory or responsiveness certificate.

## Evidence and unfinished workflow

Focused cases run both pinned versions and all four loaders: safe require, original require, dofile and loadfile. They cover renewal, original-byte preservation, private module edits, root offset shifts, removed-import archives, stale context/hash/profile/target refusal, duplicate inputs, explicit historical missing data, modeled compilation errors, archived input limits and byte-equal provenance. Actual application/staging subprocesses reopen and inspect new private modules after every original and new source file is removed, and reject changed saved private inputs. The private-display GUI test for both versions opens the three-file model, compares/keeps a source edit, checks unchanged private captures, saves/reopens and undoes the graph change. The resulting source-inspector screenshot was visually inspected.

The [external merge backend](source-text-merge.md) now reviews private captures and archives alongside original views. Each removed private view needs an exact archive or discard choice, including unchanged captures and equal-byte inserted provenance. Archival preserves captured identities and piece revisions, remaps colliding local IDs and carries no old bindings into the fresh incoming graph. Fresh application/staging reconstruction checks the resulting inactive data without reopening its paths. The immediately preceding private-input model can migrate with its entire active/archived layer preserved; earlier writers still cannot introduce that field.

Still required: the graphical fresh-folder approval and pending-request resolution workflow, graphical mapping/archive/discard choices, explicit reuse/activation, cancel/generation/lifetime integration and complete end-to-end multi-file acceptance. The internal transaction and data layer are not a full E03/E05, general language/ownership, preview, apply, security or release certificate.
