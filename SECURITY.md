# Security policy

Only the newest published development revision is currently maintained. There are no stable releases or guarantees suitable for unattended live configuration changes.

Use GitHub's private vulnerability reporting for a security issue (when enabled), or contact the maintainer privately through their GitHub profile. Do not publish private config files, tokens, screenshots containing secrets, or weaponized configurations in a public issue. Ordinary bugs can use public issues with synthetic reproductions.

## Current boundaries

- Dependency review additionally supports explicit folder grants through live O_PATH descriptors transferred over a private SCM_RIGHTS channel. Saved identity data cannot restore those grants. A fresh capture helper checks directory device/inode/mount/UID/GID/mode, resolves selected files with openat2 containment and explicit symlink evidence, then grants only the contained regular leaf's read access before capturing bytes. Folder approval itself reads no configuration content. Metadata-only probes also read no source bytes and keep contained ENOENT/ENOTDIR observations separate from denied access, authority/link changes, unavailable isolation, budgets and transport/I/O uncertainty. Those point observations alone do not prove a stable directory, readability or actual loader precedence. The captured-resolution coordinator records candidates in order and stops on unavailable/unknown evidence; it does not certify a simultaneous filesystem state or complete native/custom searcher fallback. The GUI bounds grants/captures/analysis under a combined estimated 8 MiB retained-data budget, rejects changed draft generations/epochs and clears temporary state on close. A UI-only half-second token check cancels stale open analyses; no filesystem polling or compositor calls are added. This is not full dependency evaluation, concurrent filesystem certification or a preview sandbox; see [dependency capture](docs/dependency-capture.md) for exact policies, evidence and limitations.
- Imported text is data. Legacy commands, source directives and arbitrary Lua are not executed. Lua projection uses a restricted evaluator over syntax nodes. Ordered module evaluation additionally invokes the system Lua 5.4 compiler in text-only mode, with an 8 MiB allocation budget and a 4 KiB diagnostic limit, to reject semantic compilation errors before recording statements. It opens no Lua standard libraries and never invokes bytecode or Lua callbacks. The native compiler/library is part of the parser trust boundary. Reports include the header release and linked library identity; only recorded matching Lua patch profiles supply an error-call line convention. This does not detect the target compositor dependency or certify patched libraries, full dependency behavior or fuzz coverage.
- The new `ReplayModules` worker request accepts only bounded immutable bytes and explicit resolution bindings; it cannot read paths. Bindings are supplied observations/hypotheses, never filesystem evidence or permission. Source hashes, source spans, loader kind, package path, its unknown-tail flag and working-directory context bind each request. An uncaptured inherited tail survives local copies and restoration; literal replacement supplies a known path. Operations requiring unknown bytes remain model uncertainty, not catchable Lua errors. Unknown native calls, searcher mutation, uncaptured global state and unsupported language behavior stop evaluation. Model uncertainty and budgets cannot be swallowed by `pcall` or safe-require fallback. Observations have an aggregate output quota, including repeated table expansion and loader paths. Actual missing-file/searcher diagnostics are not invented. See [ordered module evaluation](docs/ordered-module-evaluation.md) for remaining semantics and limits.
- Untrusted Lua parsing/copy preparation runs in a separate child with an empty environment, closed inherited descriptors, no-new-privileges, a seccomp syscall allowlist, 512 MiB address-space / 8 MiB stack limits, a two-second CPU limit and a three-second parent wall-clock limit. Filesystem opens, network sockets, process creation, signals to other processes and program execution are denied after startup. Unsupported architecture/kernel isolation fails closed. This does not certify compositor-preview isolation.
- Worker envelopes/replies are limited to 4 MiB. Source documents are limited to 1 MiB. Draft generations prevent a late parser result from replacing newer edits. SHA-256 source identities and expression spans guard copy preparation; no original source is published or overwritten.
- Explicit Lua/legacy import, source verification and changed-source comparison use a separate capture child. Trusted metadata-only resolution holds the selected regular inode and up to 32 symlinks, rejects procfs magic links, cycles, broken links, FIFOs, devices and directory targets, then enforces Landlock ABI >= 3 before reading source bytes. Only that inode receives READ_FILE; hard-link aliases of the same inode share this authority. A distinct seccomp policy denies network/process creation, execution, dedicated mutation syscalls and ioctl; Landlock denies writable/creating/truncating opens. Metadata access is not hidden by Landlock. The parser remains a different no-filesystem child. Missing required isolation fails closed without the old thread reader fallback. See [capture boundary and evidence](docs/source-capture.md).
- Capture requests/replies are bounded to 32 KiB / 8 MiB, source files to 1 MiB, address space to 512 MiB, stack to 8 MiB, CPU to two seconds and open descriptors to 64. Environment/inherited descriptors are cleared and parent death requests child termination. One capture lease is held through cleanup. After process creation, a three-second response budget triggers kill and asynchronous reaping without waiting on unfinished pipe threads; another capture is refused while cleanup remains outstanding. This prevents an accumulating queue but cannot guarantee termination of a kernel-uninterruptible remote/FUSE operation. Workspace/value-draft and installed keyboard metadata readers still use bounded regular-file reads off the GUI thread and lack this process boundary. Complete directory authorization/race/alias/mount certification, whole-program I/O deadlines and remote/FUSE teardown remain open.
- Draft JSON rejects duplicate setting IDs, bounds map size and key length, denies unknown structural fields, validates all setting IDs against the selected snapshot, checks value types and finite numbers, and limits text size and gradient stops.
- Source identities are captured from the same opened descriptor as the bytes, with pre/post metadata consistency checks and post-capture checks of held symlink identities. Saved identities and byte-safe selected/resolved paths are untrusted provenance and never confer file access or write authority. Path displays escape control/bidi characters and invalid UTF-8 bytes. Verify Source File refuses changed bytes; identical bytes with changed paths, link chains or metadata require review. Compare Changed Source instead prepares a separate three-way static declaration plan, binds source/report/draft/catalogue fingerprints and the GUI generation, requires conflict choices and partial-projection acknowledgement, and atomically replaces only the in-memory snapshot/draft with an inverse undo operation. Unknown projection is never treated as unset. Capture does not certify that the file remains unchanged later; no file authority or live writer follows from acceptance. Generated-file manager detection and a complete ownership/dependency graph remain outstanding.
- Workspaces pin the exact upstream commit and bundled catalogue SHA-256, validate source hashes, reject unknown fields/duplicate source IDs and are capped at 8 MiB serialized / 4 MiB cumulative source bytes / 32 source documents / 1 MiB per document. The GUI accepts a single Lua root. Recorded paths are not opened on restore, and no parser reports/ranges are stored: source is reparsed by the restricted worker. Source and identity changes participate in unsaved-close/import guards. Background save completion cannot clear edits from a newer generation.
- Workspace declarations have strict IDs/field/value validation, a separate schema pin and 1,024-rule / 128-option / 1 MiB serialized limits. Selector clauses have builder/version limits; unresolved literals are retained without runtime validation. The static parser never runs empty-workspace hooks or creates workspaces. Imported layout-option scalar types are retained. Source-copy review blocks omitted workspace edits. The optional source probe compiles only reviewed, exact-hash merge functions against inert test objects in temporary directories; it is not a sandbox or compositor preview.
- Binding drafts are data, capped at 10,000 binds, 128 submaps, 32 chord tokens, 64 actions per bind, 128 device targets and 4 MiB serialized graph data. Constructors/variants/fields are whitelisted against pinned metadata; numbers must be finite. Source callback projection never runs Lua or invokes dispatchers. Focused recording uses GTK keyboard events only, with blur/unmap cleanup and a ten-second limit; no `/dev/input` access, global shortcut registration or compositor input capture is used. Static name/reference checks do not establish effective device routing or safe recovery. Source-copy review refuses omitted binding edits and refuses invalid graph comparisons. Saved binding/action schemas are hashed independently. System libxkbcommon is used only for keysym-name lookup; its library is part of the platform trust boundary.
- Device declarations are limited to 128 ordered rules and 1 MiB serialized, with strict identities/fields/types and an audited schema pin. Category selection is a draft hint, not hardware authority. Installed keyboard choices come from the fixed evdev XML path through bounded regular-file reads, then a parser child with the existing syscall/resource limits. Registry XML is limited to 1 MiB and 16 levels; records/text have quotas, duplicate identifiers fail, and custom/external entities are rejected. Option groups are expanded lazily. Keymap selection stores a path without opening or compiling it. No keyboard, pointer or tablet setting is applied. Source-copy review blocks omitted device edits.
- Monitor rules are draft declarations, capped at 64 rules and 1 MiB serialized. Their fields are bound to the audited monitor schema; duplicate JSON keys, unknown fields, invalid selectors/values, conflicting reserved-area aliases and literal mirror cycles are rejected. Static Lua monitor import runs inside the existing restricted parser. ICC selection retains a path reference without decoding a profile. The layout diagram never queries or mutates hardware; it is not a sandboxed compositor preview. Monitor source-span editing/reconciliation and live application are unavailable. Scalar source-copy review is blocked when it would omit monitor draft changes.
- Undo retains inverse field/value changes and shared immutable source snapshots with rolling operation/estimated retained-data quotas. Oversized inverse operations are rejected before model mutation. This estimate is not a full process-memory ceiling; persistent checkpoints/history and stress profiling remain outstanding.
- Draft storage uses an owned state root, a private 0700 app directory, held directory descriptors, no-follow opens, exclusive 0600 temporary files and atomic no-overwrite publication. Draft data is synced before publication; temporary-file removal is included in the directory sync. Invalid or symlinked destinations fail closed.
- Read-only compositor IPC exposes two fixed query variants: version and descriptions. Session selection comes from the launch environment. Runtime/lock ownership, held pidfd/start ticks, executable fingerprint, held socket-node descriptor/device/inode and Unix peer credentials are checked; requests use two-second absolute deadlines and replies are capped at 2 MiB. Values from unknown commits remain unmapped; malformed data fails closed. The compositor must be visible in the caller’s process namespace.
- The app opens no network listener, performs no telemetry and has no compositor mutation or config publication interface. Clipboard export is an explicit user action; the desktop clipboard may be visible to other applications.
- GTK color/font rendering and dependency vulnerabilities remain part of the platform trust boundary. This editor is not a sandbox for malicious native code.

Captured configuration-table inspection retains raw keys separately from native NUL-truncated registry keys. Dotted/nested/NUL aliases addressing one setting within a call remain ambiguous; table iteration does not confer a winner. Candidate coordinates/expression IDs are evidence inside an immutable analysis, not ownership or edit capabilities. Native codec acceptance remains unverified. Cyclic unknown-table traversal and per-call budget exhaustion produce partial results. Per-call 512 KiB encoded evidence and traversal quotas share the existing coordinator/session bounds. This enables no source mutation or native operation.

## Before live apply or preview

Implement the blueprint's session pinning, capability separation, watcher handling, transaction journal, independent recovery agent, bounded IPC and isolation probes. Config verification must not execute imported Lua on the host. A failed sandbox probe must not fall back to the user's live compositor. Memory and CPU budgets must be measured. These are implementation gates, not currently completed protections.

Analysis Context records user-supplied home/working-directory and inherited-path hypotheses. Context folder selections never create directory grants or prove effective runtime state. Unknown and known-empty inherited paths remain distinct. Applying context clears old analysis, increments the operation epoch, counts retained context against the review budget and refuses stale/closed or pending sessions. Exact template presentation preserves byte escapes and refuses malformed/NUL/oversized input. The folder builder refuses separator/substitution metacharacters rather than quietly changing template semantics. This does not certify automatic effective-context discovery or arbitrary environment-derived home values.

Per-value expression IDs are temporary editor evidence, independent of Lua equality/cache identity. They reference immutable supplied document indices/spans and never confer file or writer authority. The origin arena is bounded to 8192 nodes/32768 edges/256 frames and shares the estimated output budget; exhaustion cannot be swallowed by Lua pcall. Graphical source details have separate traversal/text caps and escape source/path control bytes. Selected-value and executed-child edges are not a complete ownership/def-use/control or table-key proof. No source mutation, source fetch or new native operation is enabled by this metadata.
